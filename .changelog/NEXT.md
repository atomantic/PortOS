# Unreleased

## Changed

- **Daily Log no longer parks autosave when voice dictation lands mid-edit.** A spoken segment is merged into the textarea (append-at-end, caret restored) instead of leaving the user to Save or refresh, and full-content saves send the last-seen `updatedAt` as `ifMatchUpdatedAt`. When a concurrent append advances that clock, the server returns 409 `STALE_JOURNAL` with the current entry in `context.entry`; the client folds in any missing voice segments and retries a few times so an in-flight PUT cannot silently drop dictation.

- **Series Autopilot can learn which models actually work at each step.** AI run history now distinguishes technical completion from a later editorial keep/revert decision and aggregates evidence by orchestration step, creative-versus-judge role, provider, model, and reasoning effort. The new opt-in selector requires multiple quality-reviewed samples plus a positive reliability threshold, ignores disabled providers and removed models, and remains a soft default beneath explicit run choices and exact prompt-stage pins. The Options panel reports how much attributed and quality-reviewed evidence exists, while local APIs expose the full metrics and allow an operator to correct or backfill a historical outcome, including its effort when the older run predates effort telemetry. Concurrent metadata updates for one run are serialized so provider telemetry cannot overwrite its Autopilot step/role attribution, and internal structure-verification calls retain the judge role instead of inheriting their repairer's creative role. Foundation judges record contract-valid responses separately from true editorial approval, and foundation repairs automatically record accepted versus rolled-back outcomes. Arc repairs now do the same after normal rounds, corrective retries, and isolated-finding attempts, while canceled candidates remain deliberately unevaluated, so a model that finishes a long run but makes the story worse is not learned as a success.

- **Series Autopilot can route individual steps to specialist models.** A run may now override provider, model, and reasoning effort for the creative or judge role of one named orchestration step, from either the start API or the Options panel. Stage routes survive pause/resume, take precedence over learned and run-wide choices, and remain soft defaults beneath exact prompt-stage pins, so a weak foundation repair model can be replaced without repointing episode drafting or independent verification.

- **A reverted foundation repair now gets another attempt instead of ending the run.** A repair whose independent re-judge showed no gain for the dimension it targeted was correctly rolled back to its pre-repair checkpoint — and then treated as terminal, so a run configured for twelve foundation rounds paused after a single rejected attempt. The gate now retries that dimension from the verified checkpoint, telling the next attempt what was reverted and what the rejected re-judge still reported so it can change strategy, and reusing the rewound verdict rather than paying for an identical re-judge. Retries stay budget- and cancellation-gated, count against both the round limit and the existing per-dimension stall patience, and never retain an unvalidated edit; a rollback that fails its own checkpoint verification still stops immediately.
- **Foundation structure repair retains shrinking corrective progress.** A broad structure rewrite whose specialized arc verification improved from many blockers to a smaller residual used to get one correction attempt and then roll the entire improvement back. The repair now continues a bounded correction sequence while the blocker count stays monotonic, still restoring the original checkpoint if the set grows or cannot clear within the cap.
- **A late structure-repair regression no longer erases an independently verified improvement.** The bounded correction sequence could shrink nine arc blockers to one, then let its final attempt trade that residual for five and restore the entire pre-repair plan—discarding the proven one-blocker checkpoint. It now restores the best verified intermediate state, sends that partial improvement through the harsh foundation re-judge, and leaves the full arc gate dirty so the residual must still clear before beats. Model evidence follows the same transaction boundary: the retained repair runs remain provisional, while the regressive run is immediately scored as rejected; a fully reverted repair is also a rejection rather than a schema-invalid response.
- **Character-first planning now includes the cast's visual foundation.** The pre-arc character architect used to complete psychology and relationships while its response contract omitted physical description, silhouette, visual identity, and palette, so a graphic-novel series could settle its plot around characters the image pipeline still had to invent. Those identity-bearing fields now participate in completeness, prompt hashing, harsh foundation scoring, and repair; optional sheets such as props, expressions, gestures, and wardrobes are authored when the character's form supports them.
- **Character-first planning now finishes supporting cast bible cards too.** A character minted by series extraction could be omitted from foundation repair until their name appeared in the synopsis, and the repair allowlist dropped otherwise-useful profile fields such as pronouns, age, accent, likes/dislikes, mannerisms, and skills. Explicit `sourceSeriesId` ownership now keeps every series-linked character in exhaustive batches, and full narrative/visual profiles participate in completeness, hashing, repair, and harsh judging instead of stopping when only the lead framework is ready.
- **AI character expansion now finishes the whole visible bible card.** The expand action previously omitted physical description, personality, background, and outfits from both its response contract and no-clobber merge allowlist, so a technically successful run still left major UI sections empty. Those fields now fill alongside identity, motivation, framework, visual details, palettes, props, expressions, and gestures while every authored value remains protected.
- **Foundation judges now inspect the character designs they score.** Completed render fields were previously collapsed to the word `ready` in the judge context, so a harsh judge could only see that a value existed and then reasonably report that no anatomy, silhouette, palette, or visual grammar was available for comparison. The bounded context now carries the actual distinguishing details while still excluding unrelated universe assets.
- **Series Autopilot can pause without killing productive work.** The live control used to offer only Stop, which terminates the active provider run even when a long foundation judgment is doing useful work. **Pause safely** now records a graceful request, lets the active step and any provisional repair-verification transaction settle, then persists a resumable manual pause; **Stop now** remains available as the immediate emergency control.
- **Canon readiness now repairs manuscript-supported blanks before blocking art.** Autopilot's pre-render gate could identify a drawn character, place, or object with no description, but it immediately paused even though the Nouns workflow already had a safe fill-blanks-only service. The gate now runs that strict prose-grounded backfill for each affected issue, rechecks shared canon, and pauses only for locked nouns or visual facts the manuscript genuinely never established—never inventing unsupported design to force a pass.
- **Legacy canon prompts can be promoted into their missing description fields.** Universe expansion and promotion historically persisted image-ready `prompt` text while leaving the canonical `physicalDescription`/`description` blank, so the Cast/Places/Objects tabs and readiness gate disagreed with the renderer. A deterministic fill-blanks-only API now copies that already-authored text without an LLM call, preserving locks, IDs, kinds, prompts, and every existing asset.

- **Arc verification can now repair the per-character milestones it judges.** The verifier already read canonical per-character arcs, but its resolver could only edit the series arc, volumes, and issue synopses, so a contradiction in a character transition was impossible to close and repeated retries rewrote unrelated records instead. Finding-keyed character-arc patches now preserve character and transition IDs, merge only named fields, participate in regression rollback, and migrate existing prompt installations to the sparse contract.
- **Arc verification repairs long prose without rewriting the whole plan around one sentence.** A localized finding inside a volume synopsis previously forced the model to return the entire field, so a one-clause correction could rewrite more than 8,000 characters, introduce unrelated continuity failures, and be clipped at the storage limit. The resolver now emits bounded exact-match replacements for arc summaries, protagonist arcs, volume synopses, and ending hooks; missing, ambiguous, wholesale-long-field, and over-limit patches fail closed while legacy customized prompts keep their existing contract. Each prompt carries measured current/max/remaining field lengths so the replacement fits on its first attempt, and a rejected exact-only response is recorded as a no-op and retried without paying an independent judge to reread an unchanged plan or misclassifying latent findings as repair regressions. A graceful Pause requested during arc convergence now lands immediately after the active independent judgment instead of silently dispatching another repair/judge pair.

- **Completed CoS agents no longer strand a worktree because of their own completion marker.** The `.agent-done` sentinel is consumed before worktree cleanup, but Git still reported the untracked file as ordinary authored work and the safety gate preserved the otherwise-clean checkout with a high-priority warning. Cleanup now ignores only that runtime marker: sentinel-only trees are removed normally, while any real source change still preserves the worktree and is named in the warning.

- **A failed CoS task now diagnoses itself and comes back on its own.** A failing task used to pile up a queue of approval-gated tasks — the crash filed one, the provider failure filed another, repeated orphaning filed a third — and then, even after the cause was fixed, the original task sat `blocked` until someone un-blocked it by hand (or the 14-day reaper quietly retired it as stale). Both halves of that are now automatic. Every failure-driven investigation is filed through one producer, so they share a single approval policy, a single storm counter, and a single dedup fingerprint: unattended by default, held for you in exactly the two cases where another unattended agent would just repeat itself — the same cause was already investigated in the last 24 hours, or failures are cascading rather than isolated — and the task says which of the two it is. Completing an investigation, whether an agent finished it or you fixed the cause and ticked it off, then automatically retries every task that failure was blocking. Bounded at two automatic retries per task, after which the task stays blocked and says the retry loop gave up rather than still showing the original failure. A task you terminated or paused, one parked awaiting your arbitration, and one waiting on a repository path you have to fix are never revived behind your back.

- **The bundled local-LLM install catalog has been refreshed to the current model landscape.** Every suggested model was re-verified against the Ollama registry and the Hugging Face API, and the list is now built from what's current: Qwen3.5 / Qwen3.6, Gemma 4 (12B alongside the existing 26B/31B), Muse Glimmer, GLM-4.7 Flash, Granite 4.1, Ministral 3, Nemotron 3 Nano (including a 1M-context 30B), Olmo 3.1, LFM2.5, Qwen3-VL, MiniCPM-V 4.6, EmbeddingGemma, and the Ornith / North Mini Code / Devstral Small 2 coding tier. Models superseded by two generations were retired (Llama 3.1/3.2/3.3, Qwen2.5 + Qwen2.5-VL, Mistral 7B, Gemma 2, Phi-3, DeepSeek-R1 Distill, LLaVA 1.5, Code Llama, SmolLM2, Moondream) — but they still map exactly across backends, so migrating an older Ollama library to LM Studio doesn't degrade to a guessed name. Two entries were broken outright: the LM Studio repos for LLaVA 1.5 and Code Llama now 404. Ollama ids are checked for real local weights, because several headline 2026 models (Mistral Large 3, GLM-5.2, DeepSeek-V4, MiniMax-M3, Kimi K3) are published only as `:cloud` passthrough tags that would have installed nothing.
- **Local-model capability detection caught up with the models it now recommends.** Gemma 4 and Granite 4 report tool use (Gemma 3 genuinely couldn't, which is why the old rule stopped at Gemma 3), Gemma 4 reports vision, and Ornith / LFM2 / Olmo 3 / Muse Glimmer / North Mini Code / FunctionGemma are recognized as tool-callers — so they stop being hidden from agent and caption pickers on LM Studio, where PortOS has only the model id to go on. `embeddinggemma` is now correctly identified as an embedding model: it glues the marker onto the family name, slipped past the anchored `embedding` rule, and would otherwise have been offered as a chat model (the nomic-embed-text fallback bug). The editorial-model recommender learned the new families and now declines vision *specialists* (`*-VL`, `*V`, OCR) while still happily using a general model that can read images.
- **Series Autopilot now protects the author’s originating story intent.** The Universe Builder starter idea is included in foundation-cache invalidation, rendered ahead of derived canon for the independent foundation judge, and supplied explicitly to arc generation with a hard rule against replacing its ontology, protagonists, or core story engine. Full-control runs still unlock derived world fields, but they keep the human-authored starter idea locked.
- **Character-first foundation repair gets a quality-first runtime.** Productive ensemble work may run for up to twelve hours instead of being discarded at ten minutes, matching the pipeline's other long-form editorial calls while operator cancellation remains available for a genuinely hung provider.
- **Episode synopsis revisions are now restorable.** Text-stage history snapshots preserve input-only stages as well as generated output, so regenerating an episode plan can no longer discard the prior synopsis merely because that planning stage stores its authored text in `input`.
- **Series Autopilot now validates the arc spine before spending on episodes.** A protected-intent checkpoint runs immediately after the macro arc, uses only canon demonstrably tied to the current series, honors the recommended volume count (including a single 12-issue volume), and blocks or auto-corrects an incompatible premise before issue generation. Existing empty issue placeholders are reused as an exact set so their ids, history, and visual links survive episode seeding.
- **Stopping Series Autopilot now stops the active AI run.** Direct arc, episode, foundation, correction, and fallback runs publish their concrete run ids to the conductor, so Stop no longer waits for a long provider call to finish. Runs History also exposes Stop for active rows.
- **Runs History safely displays structured model output.** Prompt and output endpoints are read as plain text, preventing valid JSON completions from crashing React when a run is expanded.
- **Arc auto-resolve keeps corrections field-scoped and within storage limits.** A resolver fixing one synopsis now omits unrelated volume fields instead of paraphrasing them, and its prompt carries explicit headroom below every persisted arc/volume string cap so a well-intended rewrite cannot be silently clipped into the next verification failure.
- **Arc verification preserves its best demonstrated draft.** Any auto-resolve pass that raises the total blocking-finding count now pauses immediately and restores the lowest-blocker arc snapshot seen in that gate, even when the verifier describes the added problems as newly surfaced findings. Equal-count rounds advance the checkpoint because narrower replacement findings can reflect real causal repairs; divergence and max-round exits therefore keep the latest verified best state instead of rewinding useful work or preserving whichever unverified rewrite happened to run last. Because that guard is deliberately blind to finding identity, it can fire on a round that genuinely closed the problem it was handed and merely exposed latent defects — so a pause that rewinds now also reports the discarded round's own findings, collapsed beneath the restored set, making the trade reviewable instead of leaving only a count behind. The same accounting covers the foundation structure repair, whose revert previously reduced the arc blockers that condemned the rewrite to a number in its pause message while the findings it listed were the unrelated dimension-level gaps.
- **Foundation repair distinguishes a deeper critique from a stalled rewrite.** When a harsh re-judge holds a dimension at the same coarse score but identifies a genuinely different underlying gap, that new layer receives its own bounded repair window. Fuzzy-matched paraphrases of the same problem still accrue toward the divergence guard, so the loop remains finite instead of pausing simply because one successful fix exposed the next weakness.
- **Foundation repairs must now earn their edits.** Before each world, character, structure, or craft repair, Series Autopilot checkpoints the complete foundation — universe prose and cast, series arcs and voice, volumes, and episode seeds. The next independent judge keeps a candidate only when its target dimension improves, or when a tied score exposes a genuinely new layer without lowering the weighted result. A repair that leaves its assigned problem unchanged or makes it worse is restored and verified immediately, then pauses with both the retained and discarded critiques instead of spending another long call on a worse baseline.
- **Foundation structure repairs cannot strand a newly contradictory arc.** Every judge-directed synopsis rewrite now snapshots the current plan, runs the specialized arc verifier, gives any new canon/location/timing blockers one bounded corrective pass, and restores the snapshot if that pass is still not clean or errors. The verifier uses the run's independent judge model while corrections stay on its creative model, and the extra calls are counted against the run's usage budget.
- **Continuing a video carries its prompt forward.** Continuing or extending a clip we generated now prefills the Video Gen prompt (and negative prompt) with the one that produced the source, instead of dropping you into an empty box. This covers both entry points: the **Continue** action on a video card/lightbox, and picking a prior render in Extend mode. Text you typed yourself is never overwritten — only a blank box or a value an earlier pick filled — and a clip we didn't generate (an import, or a legacy render with no stored prompt) leaves the field alone rather than clearing it. The style preset is dropped along with the prefill, since history stores the already-composed prompt and re-applying a preset would prefix it twice.
- **Subscription Usage cards now lay out in four quadrants.** The provider quota grid orders Claude, Antigravity, Codex, Grok — and because Codex and Grok typically report only a single weekly meter, they now share one grid cell stacked vertically instead of each stretching to a full-height card. Cards render at their natural height, so the Image Gen card floats into the fourth quadrant and the whole section fits above the fold on desktop.

## Fixed

- **The prompt-drift baseline caught up with the arc-resolve migration, un-reddening `main`.** Migration 254 shipped a new `pipeline-arc-resolve.md` and correctly recorded the prior default as an accepted-old hash, but the independent baseline in `scripts/setup-data-drift.test.js` still named the superseded hash as current — so the drift sweep disagreed with the migrations it mirrors and the suite failed on every commit after it landed. The baseline now carries the shipped hash and lists the previous one among the accepted-old set. The guard itself is unchanged and still fails when a migration ships a hash it doesn't export.
- **Body stats on the MeatSpace Overview card no longer show raw float precision.** A unit-converted weight rendered every binary digit it carried (the shape `170.35000000000002 lbs`), blowing out the tile's line and implying precision the measurement never had. Weight, body fat, lean mass, and the body-composition chart's tooltip now share `formatWeight` / `formatPercent` from the client formatters, which round to one decimal, drop trailing zeros, and render a dash for a missing reading instead of a coerced zero.

- **Labels floating over 3D and Three.js previews now follow the active theme.** The status bar on a generating Three.js model read as dark green text on a near-black slab — that chrome was written as a fixed black scrim with white text, and on a light theme the white text is remapped to the theme's dark ink while the black scrim stays black. Overlay chrome across the 3D and Three.js surfaces (the generation status bar, the preview's background/explode and part-selection panels, the orbit hint and articulation badge, the mesh viewer's display-settings button, and the "Change image" labels on both pickers) now takes its surface and ink from the theme itself, so it matches the page and stays legible over a dark canvas, a light one, or a photograph.

- **PortOS no longer boots to a blank white page when it can't reach the public internet.** The app shell pulled Inter and IBM Plex Mono from `fonts.googleapis.com` as a render-blocking `<link rel="stylesheet">`, so on any install with no route to Google — no WAN, a DNS sinkhole, an outbound firewall — the browser held the first paint until that request timed out. Measured on a live install: **~60 seconds of blank white page on every single navigation**, with no console error to explain it. The service worker made it durable rather than causing it: `public/sw.js` deliberately caches the font hosts, but `cacheFirst` can never populate that cache when the fetch never succeeds, so each navigation re-hung — the exact opposite of the offline app shell that service worker exists to provide, on a product whose documented deployment is a private Tailscale network. The stylesheet now loads non-blocking (`media="print"` flipped to `all` on load, with a `<noscript>` fallback), so first paint no longer waits on a third-party host. Nothing regresses when the fonts *are* reachable: only the `lumen-glass-day` theme puts them at the front of its stack, every stack in `themes/portosThemes.js` falls back to system fonts, and the sheet still applies the moment it arrives. A guard suite pins the shell so no future `<link>` can make boot depend on a cross-origin host again.

- **One over-long character-arc field no longer bricks every save on the Series settings page.** The arc editor's inputs — character name, want, need, start/end state, transition label, at-issue — carried no length caps, while the PATCH route enforces `CHARACTER_ARC_LIMITS` with Zod. Because `updateSeries` replaces `characterArcs` wholesale, Save re-sends the entire arc list every time, so a single field over its cap rejected the **whole** series PATCH — name, logline, premise, style guide and all — and kept rejecting it on every subsequent attempt, with only a raw validation path (`characterArcs.4.transitions.3.label`) to go on. (Seen repeating across hours of a live install's server log.) The inputs now cap at the server's limits, and a parity suite fails if the mirrored caps ever drift from `server/lib/seriesCharacterArc.js`.

- **LoRA cards no longer show a permanently broken thumbnail for video previews.** Civitai`s `images[]` is really a media list — entries carry `type: 'image'` or `type: 'video'` — but the preview picker only sorted by `nsfwLevel`, so a version whose least-explicit entry was a clip stored an `.mp4` URL that the card then rendered in an `<img>`. Videos are now skipped when picking a preview, and a version with no still image yields none at all so the card falls back to its placeholder. Applied on read as well as on install (mirroring the existing URL normalization), so already-installed LoRAs recover without a reinstall.

- **Brain Memory and Media History no longer paint every record at once.** A live install with ~1.5k imported ChatGPT memories was mounting full Markdown trees for every card (~180k DOM nodes / multi-MB of text), and Media History mounted ~1.8k gallery cards with images in one grid — both tabs froze on open. Memory now shows a plain teaser for imported transcripts (full thread still opens in the conversation viewer) and both lists use a progressive "Show more" window so search still covers the full set while only a page of cards mounts. CoS 3D avatars also probe WebGL before creating a canvas, so headless/no-GPU displays degrade to a hint instead of unhandled `WebGLRenderer` rejections.

- **The pre-episode arc-spine check now resolves at the altitude it judged at.** That checkpoint deliberately verifies the arc spine with the episode lineup hidden — no episodes have been planned in earnest yet, so it only asks whether the premise, principals, engine, and volume allocation are safe to expand. The auto-resolver behind it, though, was still handed the full episode lineup and the general "correct an episode synopsis when the contradiction originates there" instruction, so it answered spine findings by rewriting episode synopses the gate had never read. Those edits could not close what was flagged, the arc and volume text stayed unfixed, and the next spine verification came back with twice the blockers — a round that got reverted wholesale and paused the run. (Observed on a run that went in with 3 blocking findings, spent its round editing 3 episode synopses, and came back with 6.) Spine rounds now render the resolver the same episode-empty plan the verifier saw, tell it to fix the arc and volumes only, and discard any episode edits it returns anyway, so a customized or stale installed prompt can't re-open the blast radius. Nothing changes for the full arc gate that runs after episodes exist: it still verifies and repairs episode synopses, which is the only place an episode-scoped contradiction can converge. Sparse finding-keyed patches and the blocker-count rollback are untouched.

- **Arc rollback now rejects equal-count severity regressions.** The best-draft guard already reverted any auto-resolve candidate that increased the total number of blocking findings, but an unchanged count was always accepted as a potentially narrower restatement. That allowed a resolver to trade a medium continuity gap for a new high-severity canon violation while still reporting the same total. Equal-count candidates are now ordered by severity before they can replace the checkpoint: more high findings, or more medium findings at the same high count, is a regression and is reverted through the same bounded corrective-pass path. The pause message names the severity escalation explicitly instead of presenting two identical counts as if one were numerically larger.

- **A reverted arc auto-resolve round no longer ends the whole run on its first bad attempt.** Arc verification correctly refuses to keep a resolver rewrite that raises the blocking-finding count — but it then stopped the run and asked you to fix the arc by hand, and resuming just re-ran the identical prompt against the identical restored plan, so the gate could regress the same way forever. (Observed on a spine check that went in with 3 blockers, came back with 6, and paused on round 2 of 3.) The revert still happens exactly as before; what follows it is now one bounded corrective pass. The resolver is re-run from the restored best plan, handed the findings that plan actually has, plus — this is the new information — the problems its own discarded attempt just authored, named explicitly as the failure mode to avoid rather than as more work to close. Only when that second attempt also regresses does the gate pause for review, with the same best-state residual and discarded set it reported before. A retry is never spent on the final round (nothing would verify it), it is budget-checked and billed like any other resolve, and `maxArcResolveRetries: 0` restores the previous stop-on-first-regression behavior per run. The live status line now distinguishes a rollback that is retrying from one that is about to pause.

- **A provider outage no longer hands a CoS task's model pin to a provider that can't run it.** A task pinned to Antigravity with `gemini-3.6-flash` hit an auth outage on that provider; the fallback chain correctly swapped it onto the Claude CLI but carried the Antigravity model id along, so every retry spawned `claude --model gemini-3.6-flash` and died in ~1.5s ("There's an issue with the selected model") until the task exhausted its retries and blocked. The pass-through exemption that let it through is deliberate — it exists so an explicit pin isn't silently downgraded to the provider's heaviest default just because the provider's `models` list spells an alias differently — but it only makes sense on the provider the pin was chosen *for*. A `metadata.model` pin is provider-scoped (the task form picks a provider, then a model from that provider's catalog), so a fallback swap now drops it back to the new provider's own default unless that provider actually lists it, logging the substitution rather than doing it silently. A swap between siblings that both serve the pinned id (claude-code ↔ claude-code-tui) still keeps it, and a run with no swap at all is untouched. The check also covers a fallback provider that enumerates no models, which the existing model-list validation could not inspect at all.
- **The Claude CLI's own model rejection is now a recognized, actionable failure.** "There's an issue with the selected model (…)" is printed by the CLI at startup, before any API call, so it carries no `API Error: 4NN` token and matched none of the model-error patterns. It landed in the `unknown` bucket with "Error did not match known patterns" — which autoFixer maps to Tier 4 (escalate), so a task with a bad model id burned all three retries against an id that could never work and then spent an agent run on an investigation task. It now classifies as `model-not-found` with the rejected id extracted from the message, putting it in Tier 1 (config/env) where a model correction belongs. Promoted to a structured `provider`-origin signal, since the full banner with the parenthesised id and the `--model` hint is CLI text rather than something a task's own output prints in passing.
- **Stopping the CoS Runner no longer burns through queued agent tasks.** `portos-cos` is a separate PM2 app you can stop from the Apps page, and while runner mode is active it owns every agent process — but the spawn path dispatched into it regardless and recorded the resulting rejection as a task failure. The CLI arm charged a retry each time (a runner left off overnight walked every queued task through its retry budget and into `blocked`), and the TUI arm reported an *actionable* spawn error, parking the task for a human over an app you had simply turned off. Tasks now hold instead, gated in two places: the queue stops dequeuing entirely while the runner is down — before the priority tiers drain on-demand requests, advance review cooldowns, or bind an app's "in review" marker — and dispatch itself holds anything that still reaches it, releasing that marker and freeing the scheduler's spawn reservation so an autonomous job re-registers instead of sitting wedged for five minutes. A held task keeps its exact queued record: pending, unclaimed, no agent, no retry charged. It spawns for real the moment the runner is back, because the runner socket's reconnect re-runs the dequeue. That reconnect is also now unbounded: the socket gave up after ten attempts (~10 seconds), so a runner that came back a minute later left the server connected to nothing while still routing every spawn at it. Backoff is capped at 10s and the resulting dequeue is debounced, so neither a long outage nor a crash-looping runner is expensive. You get one log line when the runner drops and one when it returns, not one per task. "Run now" is never held — it answers with the real reason (runner unreachable, or the daemon stopped, which was never checked at all) instead of toasting "Spawning" at a task that would sit pending.
- **The Antigravity account-eligibility banner no longer kills an agy run before it can start.** "We're finishing verifying your account eligibility. This usually takes a moment. Please try again shortly." is the front of agy's sign-in handshake, not its verdict — the CLI's own log shows the session authenticating fine (OAuth succeeds, the keyring token refreshes for another hour) and then retrying `loadCodeAssist` while the composer shows that notice. PortOS was treating the banner as an immediate fatal signal and killing the terminal 0.85–1.5s after the prompt was pasted, so the model was never asked for a token. Every agy CoS agent run from 2026-08-07 onward died this way in 3–5s, while the same account and model answered instantly over `--print` and over a PTY whose eligibility was already warm. The signal is now marked self-clearing: both TUI paths hold the session for up to 60s and let the run continue the moment agy starts generating, and only fail over to a fallback provider if the banner outlasts that window with no sign of life. The grace window also suppresses the idle reaper while it's armed, so a waiting run can't be finalized as a bogus `idle-complete` success that scrapes the banner as its answer. Other fallback signals (usage limits, rejected model ids) still fail immediately.

- **A foundation repair that was correctly rolled back no longer reports the rollback as corrupted.** When Series Autopilot reverted a character repair that failed to improve its target dimension, the pause said "checkpoint verification failed after rollback: restored foundation fields did not match the checkpoint" — implying the cast had been left in a half-repaired state. Nothing was actually wrong: undoing a repair is itself a content change, so the universe write path re-stamped `updatedAt` on every canon entry it restored (it has to — that timestamp is the clock the canon→catalog projection uses to carry the revert), and the verification compared those server-owned stamps byte-for-byte along with the authored prose. Every faithful character rollback therefore failed its own check. The comparison now ignores exactly the per-entry fields the write path owns and deliberately does not revert — the LWW timestamp, plus the reference-sheet and render pointers, which are preserved from the live record so a render that finished mid-repair isn't thrown away by the undo — while still comparing all authored content byte-for-byte. When a restore genuinely doesn't come back, the pause now names the fields that failed instead of stating only that something didn't match.

- **Arc verification now banks the fixes that worked instead of discarding a whole round for one bad edit.** The gate resolved its blocking findings as a single rewrite: every finding went to the resolver in one call, and the next check kept or reverted that candidate as a unit. So a rewrite that cleanly closed two problems and broke a third was thrown away in full, and the gate ended up holding nothing — on the observed run it reached a verified best of 2 blockers, watched the next pass come back with 5 and the corrective retry with 3, correctly preserved the 2-blocker draft both times, and then paused for review with seven of its twelve permitted rounds unspent. The rollback guard is unchanged and still refuses any candidate that grows the blocking set or worsens its severity mix. What is new is what happens after the corrective retry is spent: when the residual has more than one finding, the gate now takes it apart and tries the findings one at a time from the best verified plan. Each attempt is its own transaction — snapshot, resolve that one finding, re-run the same verification the gate uses, and keep the edit only when the finding it targeted is actually gone and what it left behind is not a regression by the same count-then-severity rule the whole-round guard applies — so which trades survive no longer depends on which tier judged them. Anything else is restored on the spot, so a poisoned finding now costs only its own attempt instead of its neighbours' repairs, and the surviving fixes are re-verified together before the gate is allowed to clear. Closure is judged the same way the rollback guard judges identity, so a verifier that merely restates a standing problem in fresh words can't pass as a fix. The pass is bounded by a spend budget counted in provider calls — so a wide series, whose every check costs one call per volume, gets fewer attempts rather than a proportionally larger bill — skipped when only one finding is left (that is the corrective retry again, at twice the price), never run without a round left to verify what it kept, capped per run by `maxArcIsolationAttempts`, and switched off entirely by that or by `maxArcResolveRetries: 0`. The dry-run plan now includes its worst case, so the estimate you approve a run from still bounds the gate. The live status line reports each isolated attempt and whether it was kept.

- **A local video render now tells you how long it has left, once your machine has rendered something comparable.** Local renders run 15–40+ minutes and the only progress the UI could show was a step counter — "20%" on a job that might finish in four minutes or forty, with no way to tell which. - **A generated Three.js model is now checked for parts modelled inside each other.** Every existing gate reads one part at a time — the schema proves each geometry is well formed, the coverage gate proves the assembly backs the inventory, and the cross-section gate proves the identity parts have real depth — so nothing ever compared two parts to each other, and the whole class of defect where sibling parts occupy the *same* space was invisible: a greeble modelled at the wrong scale and swallowed whole by the hull it was meant to sit on, a limb rooted a full radius inside a torso, an eye socket punched clean through the back of a skull.
