# Unreleased Changes

## Creative Director

- **A project whose stored record lost its id no longer shows up as an unusable card.** Each project is one database row: the id is a column, and the whole record is duplicated into a JSON blob beside it. Reads handed back the blob untouched, so a row whose blob was written without an id — the column still had one — reached the page as a project with no identity. Its card opened `/creative-director/undefined/overview`, and Start, Pause and Delete all acted on `undefined`. Reads now fill the id in from the column, which is the value every lookup already matches on, and the record repairs itself on its next save.

## Media Gen

- **The favourite star on an image or video card is now reachable by keyboard.** The star sat inside the card's own click-to-preview button. A button nested in another button is invalid HTML with no defined behaviour, and here it left the star unreachable by keyboard and out of the tab order. The star and the badges are now siblings of the preview target rather than children of it, so the star is focusable and clicking it still favourites without also opening the preview. Three more controls with the same defect were fixed alongside it: the Plan/Execute/Verify button on a GSD phase row, the Dashboard link on a Chief-of-Staff GSD project card, and the tag filters on a SongBook entry — each was mouse-only, and each needed a click-suppressing workaround that is no longer necessary.
- **[issue-3283] Media Collections can now be searched, sorted, and stripped of empty auto-created buckets.** Every Creative Director project and render bucket files itself away as a collection the moment it is created, so the grid filled with empty cards that all read as the same clipped `Creative Director: …` text — the trailing project name and date that told them apart were exactly what got cut off. The page now has a search box, a Recently updated / Name / Item count sort, and a "Hide empty" toggle that is on by default (with a "N empty hidden — Show" link when you want them back); collections that actually hold something, plus any you named yourself, sort ahead of the auto-generated empties; and the shared `Creative Director` prefix moved into a small badge above each title so the distinguishing tail stays readable. Your filters live in the URL, so a filtered view is shareable and survives going back from a collection, and creating a collection now opens it — a brand-new bucket is empty by definition, so the filter row would otherwise swallow the thing you just made.
- **A collection whose cover image is missing now shows the syncing placeholder instead of a broken image.** Collection covers were plain `<img>` tags, so a cover pointing at a pruned video thumbnail — or at a federated collection whose files haven't been pulled yet — left the browser's broken-image icon on the card. Covers now use the same component as the rest of the media UI: they fall back to a "Syncing" tile and swap in the real image the moment the file arrives from a peer.

## Prompt Manager

- **[issue-3284] The prompt stage list is now searchable, grouped, and safe to scroll past.** Settings → Prompts listed all 127 stages as one flat column with no search box, so finding "Creative Director — Treatment" meant scrolling a page seven screens tall and reading two-line descriptions to tell near-identical names apart — and every row carried a bare trash icon right beside its own click target, so a mis-tap while hunting offered to delete a stage instead of opening it. There is now a search box pinned above the list that filters on title, description, and stage id as you type, a SYSTEM-only toggle, and collapsible groups (Pipeline, Writers Room, Creative Director, Brain, CoS, …) built from the naming convention the stages already followed. Delete has moved off the row and into the selected stage's editor pane.

## Documentation

- **Getting started now uses the standard install and production-start commands, with PostgreSQL called out as required.** The documentation catalog also has a product-surface map, making every major area of PortOS easier to find before you need its focused guide.

## Image Gen

- **Agy and Grok can no longer hand back a picture they drew themselves.** When Antigravity's `generate_image` backend hit its quota (HTTP 429 "you have exhausted your capacity on this model"), agy did not fail the render — it took the instruction "save a PNG at this path" literally and wrote a script that drew a stand-in with a plotting library instead. The result was a real PNG, so it passed the signature check and landed in the gallery looking like a generated image: flat vector shapes, placeholder circles, overlapping labels, and the prompt's own pixel dimensions captioned into the artwork. Both cloud CLIs are now told that only the image tool may produce the image and that reporting a failure is the correct outcome when it can't; a scratch-directory check discards any render whose agent left a drawing script behind. The agy prompt also stopped naming exact pixel dimensions — `generate_image` only exposes an aspect ratio, so that was an instruction it could never satisfy, which is precisely what made reaching for code look reasonable.
- **The usage page now has an Image Gen card, observed rather than guessed.** The provider cards only ever showed the *agent* model's quota, which is a different bucket from the image backend — when the imagen backend returned 429, the Antigravity card was still reporting the Gemini 5-hour group at 78% left, so nothing on the page explained why renders were failing. These CLIs expose no image-quota API at all (Antigravity's `/usage` panel has rows for `GEMINI MODELS` and `CLAUDE AND GPT MODELS` and nothing for images), so the new card reports what PortOS actually watched happen: a real 0%-left meter with the provider's own stated reset time once a render is refused, and a plain 24h render count otherwise — never a reassuring "100% left" bar for a number nobody can measure. A block clears as soon as a render succeeds again, not merely when the stated reset passes. The card appears only when a cloud image backend is enabled; local renders use your own GPU and have no quota.

## Universe Builder

- **A failed settings load no longer resets your image-gen mode.** Opening Universe Builder fetched providers, image models, LoRAs and settings together, and treated any request that failed exactly like one that came back empty. A brief network blip therefore rendered the page as if nothing were configured — and worse, the settings read was used to recompute the render backend, so a failed fetch silently reset your saved image-gen mode to Local and the pipeline image config to defaults. Each request now keeps its last known-good value when it fails, while a genuinely empty response still applies.

## Calendar

- **The account expand toggle now announces itself to screen readers.** The chevron that opens an account's calendar list rendered as an unlabelled icon button, so a screen reader read only "button" with no indication of what it did or whether the section was already open.

## Sprites

- **The panel close buttons and the Lock/Approve controls are now big enough to tap.** The close buttons on the import and new-sprite panels were a bare 16px icon with no padding, and the reference/walk workflow's Lock, Unlock and Approve confirmations were roughly 18-26px tall — well under the 44px target the rest of the interface uses. On a phone these are the controls that dismiss a blocking panel and commit a candidate, so a mis-tap mattered.

## Internal

- **Route handlers now share one pagination parser.** Twenty-two places across fifteen route files hand-rolled `parseInt(req.query.limit, 10) || N` instead of calling the pagination helper that already existed. That spelling has two real consequences: `?limit=0` and negative values are falsy, so they silently fell back to the default rather than being clamped, and several endpoints had no upper bound at all — `?limit=999999` was passed straight through to the datastore. Every migrated endpoint keeps its previous default, and the ones that were unbounded gained a generous ceiling. Three sites were deliberately left alone because their behaviour genuinely differs: two treat a missing or zero limit as meaningful, and one uses an absent limit to mean "no limit". The helper's boundary behaviour now has direct test coverage.
- **Slashdo command loading moved out of the general file utilities.** Two hundred lines of slashdo-specific command loading and template rendering lived in `fileUtils.js` alongside generic JSON, path and upload helpers, while a separate module already owned other slashdo concerns — so working on one feature meant reaching into two unrelated modules. The loading code now has its own module, registered in the library barrel and catalog. Behaviour is unchanged: the moved code is byte-identical to what was removed.
- **[issue-3264] Fixed a development-mode freeze that left panels loading and buttons stuck after one click.** Under `npm run dev`, a mount guard used across fourteen components and hooks was never re-armed after React StrictMode double-mounts a component, so anything gated on it silently stopped updating — the music generator panel sat on "Loading generators…" forever, and every button backed by the shared async-action hook stayed disabled after its first click. All fourteen now use the shared hook that re-arms correctly, and a test fails if the broken shape is reintroduced anywhere in the client.
- **[issue-3266] The mount guard behind issue 3264 now has exactly one implementation.** Thirteen more components and hooks still spelled that guard out by hand — correctly, so the new test passed them, but they were the copy source: reproducing issue 3264 took nothing more than copying one of them and dropping a line. Several also carried their own multi-line essay re-deriving the StrictMode hazard, which is the hazard being rediscovered per file instead of read off a hook name. All thirteen now call the shared hook, and the test fails on the hand-written form whether or not it happens to be correct.
- **[issue-3265] Fixed a test that broke on its own once the calendar passed 2026-07-31.** An image-quota test compared against a reset timestamp baked into its fixture; once that instant passed, the code correctly ignored the stale time and the test started comparing against the wall clock, failing every run. The test now pins its own clock, and the ignore-a-past-reset path it accidentally exercised has coverage of its own.
- **[issue-3267] Removed the unmount guard from the shared async-action hook, along with the test that could never fail.** The guard existed to avoid a "state update on an unmounted component" warning React stopped emitting in version 18, so its only remaining effect was to skip a no-op — while being the exact shape that froze every button backed by the hook under StrictMode. Its regression test asserted that the vanished warning never appeared, which stayed green even with the guard deleted; it now unmounts mid-request and asserts the action still resolves with its value.
- **[issue-3250] Stabilize Music Video project-selection tests under CI load.** Project-selection coverage now waits for the requested project to be available before opening its board, preventing intermittent false failures.

## Chief of Staff

- **Run-history row actions and screenshot-remove buttons are now visible when you tab to them.** The view-logs, resume and delete buttons on a run-history row — and the remove-screenshot buttons on the task form and the resume-agent dialog — were revealed only on mouse hover. On a tablet, which has no hover state, they were undiscoverable; for anyone navigating by keyboard they could be focused but never seen, so you could tab onto a delete button with nothing on screen telling you so. They now appear on keyboard focus as well as hover.

## Messages

- **A message thread no longer renders under the wrong message.** Selecting one message and then quickly selecting another could let the first thread's response arrive last and render beneath the second message's header. The same stale-response fix was applied to the Feature Agents Output and Runs tabs, where switching agents mid-request could show one agent's output — and its recorded agent id — under another agent's tab.
- **Gmail can now be fully connected from Messages Config.** The page can create or accept Google OAuth credentials, returns to Messages after authorization, and labels an enabled Gmail account as pending until its Gmail permission is actually ready.
- **[issue-3281] An empty inbox now names the step that would actually fill it.** "No messages yet — add an account and sync to get started" was shown to everyone, including users whose account was already configured and whose Sync buttons were sitting directly above the message. The empty state now says what is left to do and carries the button for it: add an account when none is configured, Sync Unread when nothing has ever synced, and — once a sync has run — how long ago it was, with a Clear filters button when a search or triage tab is what is hiding the mail. A sync where every account errors no longer reports success or claims the inbox has been synced.

## Music Video

- **[issue-3245] Synced Music Video projects now use each machine's own render backends.** Image and video backend pins no longer overwrite a peer's locally usable choices, while shared model and pacing settings continue to sync.

## Video Generation

- **Clicking the "Image Strength" label now focuses its slider.** The label was never associated with its input, so unlike every other field on the form clicking it did nothing, and a screen reader announced the slider with no name.
- **[issue-3248] Requeued local videos now keep their original render controls when Grok is the default.** Frame count, frame rate, steps, guidance, seed, image strength, and tiling settings keep the render on the local backend instead of being silently discarded.
- **[issue-3279] Generate is back above the fold on the Video tab.** Frames, chunks, frame rate, seed, steps, CFG scale, image strength, tiling and the audio flags now sit behind a closed-by-default "Advanced" disclosure, leaving Model and Resolution inline exactly like the sibling Image tab — so the button that starts the render is on screen when you finish typing the prompt instead of roughly 600px below it. The collapsed header still shows the frame count, frame rate and seed a remix carried in, and every value survives collapsing.

## Sprite Manager

- **[issue-3247] Forked sprites now validate their pinned render model before saving.** Invalid model IDs are rejected immediately instead of leaving a sprite pinned to a model that later renders cannot use or replace.

## Agents

- **[issue-3246] Completed direct-CLI agents now survive a PortOS restart without repeating their work.** When an agent has already written its completion sentinel, shutdown finalizes that result and dispatches its output instead of requeuing the task and potentially opening a duplicate pull request.
- **[issue-3273] A new "UX/design audit" scheduled task reviews whether your screens are actually usable — and proposes, rather than rewrites.** The existing UI tasks are all narrow and all fix-and-commit: broken elements, viewport breakage, ARIA and contrast. None of them ask whether a primary action is buried below the fold, whether an empty state tells you what to do next, or whether two sibling screens confirm a delete two different ways. The `ux` task walks the running app against a seven-point checklist at desktop and mobile widths and files one issue per finding into whichever tracker the app uses — PLAN.md, GitHub, GitLab or JIRA — with the route, what the user was trying to do, why the design got in the way, the component file to change, and a size estimate. It touches no source code and opens no pull requests, because design judgment should be triaged by a human, not auto-merged. Off by default, like every other scheduled task.
- **Tracker-filing tasks no longer score every successful run as a failure.** A task whose whole job is to file issues makes no commit, so the commit check that grades autonomous runs marked each correct run a miss and drove the task type's measured success rate toward zero — which in turn slowed its schedule. Those tasks are now graded on whether they finished rather than on whether they committed, but only on projects where they really do file out of band: the same task still has to commit on a PLAN.md project, where recording a finding means editing a file. This also fixes the same latent problem for reference-repo watching on GitHub, GitLab and JIRA projects.

## POST

- **Mastery can now become permanent instead of decaying forever.** Facts stay mastered after three successful checks, broader skill reviews leave the schedule after three consecutive passes, and a user who already knows a memory item can attest that mastery now and verify it with one randomized future spot check; only a failed spot check returns the material to daily training.
- **Elements mastery now tells accuracy and mastery apart.** A single correct flash card can show 100% accuracy while remaining in Learning until it meets the mastery gate of three checks at 80% or better. The summary count, periodic-table colors, hover tooltip, and selected-element details all use that same rule, while facts that clear it now stay mastered.
- **Finishing a lesson now keeps the daily brain-training routine moving.** Memory lessons, scored POST assessments, standalone Wordplay rounds, and Morse practice now end with an explicit choice to save/finish for now or save and continue. Continue asks the existing recommendation engine for the next scheduled activity and opens it directly even when the routine crosses from memory into math, cognitive training, wordplay, or Morse. The Memory Builder's own "Review Next" button also starts the due practice mode instead of reopening the item's mode menu.
- **The session launcher can show which AI provider a run will use again.** The launcher read the provider list as if the server returned a bare array, but it returns an object wrapping one. The mismatch threw on every mount, was swallowed into a console warning, and left the list permanently empty — so the Wit &amp; Memory panel never showed the provider a drill was about to use unless one had been pinned explicitly.
- **[issue-3253] Powers practice now teaches a fast mental path before raising the difficulty.** New sessions begin with recall-friendly powers of two, unlock named techniques through speed-and-accuracy mastery, never generate a pair without a documented method, and show the worked steps after a miss and in session review. Manual base and exponent controls remain available when Progressive is switched off.
- **[issue-3254] Memory drills can now join Full and Quick POST sessions.** Memory remains off in Session Composition by default, but users with an enabled memorized item can opt in to interleave recall work with their daily session; empty or fully-disabled item pools are explained and never produce a broken mid-session drill.
- **[issue-3252] A new Practice Plan page decides what you're actually studying.** POST had grown to roughly thirty drill types across six subjects plus three standalone study surfaces, with no single place to say which of them you want. Practice Plan (`/post/plan`, also reachable from ⌘K and by voice) lists every topic with a switch, expandable to its individual drills, and shows a live "your daily POST will include…" summary that updates as you flip switches — so you can see what tomorrow's session becomes before you run it. Drill Config still owns how hard each drill is; Practice Plan owns what's in the rotation.
- **[issue-3252] "Wordplay only" is now one switch instead of eight.** Wordplay, Verbal Agility and Imagination all used to hide behind a single "Wit & Memory (AI)" checkbox, so keeping just one of them meant unchecking eight individual drill types by hand — and the subjects the launcher showed you weren't the ones the settings page let you edit. Each is now its own topic, and switching one off drops its drills from Full and Quick sessions and from the "Up next" recommendations together.
- **[issue-3252] Memorized texts can leave the daily rotation without being deleted.** Not wanting the built-in Elements Song in your reviews used to mean deleting it, which threw away every bit of mastery and scheduling history you'd built up. Each memorized text now has its own switch: switch one off and it stops being recommended and stops being auto-picked for memory drills, but keeps all its history and stays available to practise any time from its own page.
- **[issue-3252] Morse can be switched off if you're not learning CW.** The launcher used to suggest "Morse: keep climbing" indefinitely with no way to decline. Morse is now a topic like any other, and switching it off stops those suggestions.

- **[issue-3249] The POST launcher now opens on what to do, not on what you've done.** Starting a session meant scrolling past Today's Status, Goals, Up next, the streak and trend cards, the mode toggle and the Conditions form to reach "Quick 5 Min" and "Full POST" at the very bottom of the page. Those actions are now the first thing on the launcher, on a single Start card that also carries a one-click CTA for whatever is recommended next — the exact drill you're weakest at, a due maintenance rep, or the memory item that came due — plus the Test/Train toggle. The optional Conditions fields are tucked behind a disclosure that remembers what you typed and shows a count when collapsed, so they can't push the buttons out of view again.
- **[issue-3249] "Up next" recommendations now start the practice instead of dropping you on a page.** A due memory item like *Review "The Elements Song"* used to link at the memory list, where you still had to find the item, open it, scroll past the periodic table, and pick one of five practice modes — four clicks and two scrolls to reach an actual drill. It's now one click straight into a running drill: the Elements Song opens its recall test, and any other memory item opens spaced repetition, which targets its weakest verses.
- **[issue-3249] Every memory practice mode now has its own link.** Practising a memory item is addressable — `/post/memory/<item>/spaced`, `/post/memory/elements/element-flash` — so a drill can be bookmarked, shared, reopened after a reload, and reached from ⌘K or by voice, the same way the Morse modes already work. Browser Back now steps out of a drill to the mode list and then to your items, and the Elements Song modes (Flash Cards, Element Flash, Fill the Lyrics, Learn Lyrics) are each individually reachable from the command palette.
- **[issue-3249] The Elements Song page leads with practice and suggests where to start.** The periodic table used to fill the screen before any of the five practice modes came into view, with nothing to say which one to pick. Practice now sits at the top, and the mode that fits your current mastery is flagged "Start here" — the study deck when you haven't drilled the elements yet, the recall test while they're still shaky, the lyrics drill once the symbols are solid.

The picker now appears right away with a note that saving is required to generate, and a mode chosen before saving stays selected once the track is created.

## Goals

- **[issue-3280] The goal tree now names every goal instead of showing bare dots.** The Tree view rendered a dozen unlabelled coloured spheres whose identity was only revealed on hover — which doesn't exist on a touch device — so it conveyed strictly less than the list view beside it. Each node now carries its title on a camera-facing label sized by goal type, fading out as you pull back so a zoomed-out graph doesn't turn into a wall of words, with a Labels toggle (on by default) to quiet a dense tree. The camera also frames itself to the whole graph on open and whenever a filter or search reshapes it, so no goal starts off-screen with its edges running into empty space.

## Review Hub

- **[issue-3282] Queue cards now preview their body in three lines instead of printing it whole** — Every card rendered its full untruncated body, so a queue of 59 pending items ran roughly 56 screenfuls on desktop and 197 on a phone, and one error card alone printed a URL, a full browser user-agent string and a stack trace inline. Card bodies are now a fixed three-line plain-text preview with a per-card "Show more" that expands the full formatted text in place, titles clamp to two lines so the queue scans as a uniform list, and Accept/Reject/Complete/Dismiss/Delete stay on the collapsed card so a decision never requires expanding. Long agent-authored bodies also no longer inject their own headings into the page's outline.

## Data Manager

- **[issue-3285] Every directory on the Data Manager now says what it holds and whether it is safe to remove.** Seven of the thirteen biggest rows — including the single largest one — were labelled "Unknown category", and because an unrecognised directory also fell back to "not archivable, not deletable", the cleanup page silently refused to act on the very things filling the disk. All ~65 directories PortOS creates under `data/` are now classified with a real description and honest archive/purge flags: LoRA training checkpoints and the managed Python virtualenv are purgeable and say what survives, while generated sprite art, training datasets and 3D meshes are explicitly protected as the only copy. A directory that genuinely has no classification now reads "Not classified — PortOS does not know if this is safe to remove" and explains that Archive and Purge are being withheld on purpose, and a new test fails the build if a future data directory ships without an entry.
