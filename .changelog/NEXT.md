# Unreleased Changes

## Image generation

- **[issue-3231] Each creative surface can now have its own default image backend and model.** A new Defaults tab in Settings → Image Gen lets you pin, per surface — Universe Bible batch renders, character sheets, Series first-pass portraits, sprite references, pipeline visuals, LoRA datasets, and creative-agent renders — which backend (Local, Codex, Grok, or Agy) and, where the backend accepts one, which model that surface renders with. Anything left on Auto keeps following the install-wide default exactly as before, a pinned backend that's disabled safely falls back instead of breaking the surface, and an explicit choice made on a page still wins over the pin. Pinned models now actually reach the renderer on every one of these surfaces — previously they all silently used the provider's own default.
- **[issue-3231] Agy image renders now default to a cheap, fast agent model.** An Agy render with no model chosen used to run on whatever Antigravity's own configuration selected — potentially its slowest, most expensive reasoning tier — just to relay a single image request. Renders now default to the cheapest flash tier (matching how Codex renders already pin their light model), and a model you set in Settings or per render still wins. Settings → Image Gen → Agy CLI also now makes clear which model the field controls: the *agent* driving the session, not the image model — the image itself always renders on Antigravity's fixed server-side Imagen 3 backend, which is now named on the page and recorded with each generated image.

## 3D avatars

- **[issue-3208] Shared GLB avatars now keep their cached model resources intact by construction.** CyberCity, Chief of Staff, and generated-model views render cached or cloned scenes through one safe path, preventing future avatar additions from reintroducing blank meshes after navigation or remounts.

## Added

- **The SongBook's sample song now ships a drum part.** "House of the Rising Sun" has always seeded with guitar, piano, and ukulele arrangements, but a drummer opening it had nothing to read — only the invented "Example Rock Beat" that exists to demonstrate the grid format. A fourth arrangement now ships alongside the other three: 32 bars of 6/8 (one grid cell per eighth, four times through the 8-bar progression), with the drums sitting out the intro on a hi-hat foot pulse, entering on a pickup fill, moving from hats to the ride for the organ break, and ending on a flam into the crash. It plays back against the other three seeds at the same tempo, and the written 228 counts *eighths* — so the practice-tempo buttons take it down to a workable speed. Existing installs receive it on upgrade without ever overwriting a copy you've edited or deleted.
- **The Shell tab can now hand a photo to the agent running in it.** A new **Photo** button in the terminal toolbar (and in the fullscreen control bar) opens a small composer: choose a photo, snap one from your phone, drag one in, or paste a screenshot straight from the clipboard, type a message, and send. PortOS saves the image and types your message plus the saved image's path into the live session as a single paste, so a running `claude` or `codex` can read the picture and answer about it — the same way you'd hand it a file if you were sitting at the terminal. Enter sends, Shift+Enter adds a line; a failed send keeps your message and your picked photo so you can retry without retyping. Photos are stored under a unique name, so sending two shots from a phone (where every photo is `IMG_0001.jpg`) can't have the second overwrite the first before the agent has read it.
- **Malware scans now leave a durable, reviewable report trail.** Git-link scans save an owned markdown artifact, surface it from the completed agent summary and Review Hub, and mark repositories with an explicit `DANGEROUS` verdict using a skull danger treatment on the Git links card.
- **Slashdo-free TUI agent PRs now complete their lifecycle.** Codex, Antigravity, OpenCode, and lean Claude agents hand committed work back to PortOS so it can generate a non-empty PR description, run configured reviewers, and merge after the selected gates pass instead of leaving an ownerless PR open.
- **Music Video projects now save their scene-video renderer and model.** Directors can choose local or Grok generation per project, pick an image-to-video-capable local model, see cut-pacing warnings, selectively continue clips on native LTX runtimes, generate all missing media from the board, and play or download the audio-backed final render in place.
- **Music Video projects can now be forked into editable versions and rendered with local song-reactive motion.** A fork keeps the source board and scene media while clearing the final master, records its parent/root lineage, and opens immediately as the next version. Projects with the LTX-2.3 audio-reactive LoRA installed can condition each cut on its exact song segment while stripping generated clip audio and automatically directing the model away from singing, lip-sync, performers, and visible musical performance.
- **Music Video projects can pin an exact audio-reactive LoRA version and audit visual repetition before rendering.** The LoRA manager installs versioned HuggingFace files from the same repository side by side, recommends the LTX-2.3 Audio Reactive V2 weights at 1.2×, and the director toolbar now shows the selected LoRA plus unique-frame/unique-clip counts instead of treating repeated media as fully diverse. The local MLX runtime is pinned to ltx-2-mlx 0.14.19 and automatically prefers the improved LTX-2.3 1.1 distilled adapter when the selected Q4/Q8 checkpoint includes it.

## Agent workspaces

- **[issue-3180] Agents no longer run in the PortOS folder when your app's repository path is wrong** — picking an app as the workspace (in a CoS task, or Settings → Providers → Run Prompt) and asking the agent to create a file could put the file in the PortOS directory instead of your app. If the app's Repository Path was empty, mistyped, or pointed somewhere that no longer exists, PortOS quietly fell back to its own folder and said nothing, so the run looked like it had worked. Now PortOS names the directory it chose for every run and in the CoS task log; a run whose workspace doesn't exist stops with a message telling you which path to fix; and a CoS task whose app has no usable Repository Path is blocked before the agent starts, rather than turned loose in the PortOS checkout. A path saved as `~/Projects/MyApp` is also accepted. Troubleshooting steps — including why `PORTOS_WORKSPACE_ROOTS` is unrelated to this — are in `docs/TROUBLESHOOTING.md`.
- **[issue-3193] OpenCode agents now run in the app you selected, not the PortOS folder** — even with a correct Repository Path, agents on an OpenCode provider wrote their files into the PortOS directory and reported the PortOS path as their working folder. OpenCode decides where it is by reading an environment variable that describes the folder PortOS itself was started in, rather than the folder it was actually handed, so the workspace you picked was quietly ignored — only on OpenCode, which is why Codex, Claude Code, and Gemini looked fine. PortOS now sets that variable to the real working directory everywhere it starts an agent, a provider run, a TUI session, or a terminal. Troubleshooting steps for telling this apart from a mistyped Repository Path are in `docs/TROUBLESHOOTING.md`.
- **[issue-3180] Agent terminals on Windows get a working environment** — the environment filter for agent shell sessions was written for macOS/Linux and dropped variables Windows needs, including `Path` itself (Windows spells it mixed-case, which the filter didn't match), plus `SystemRoot`, `ComSpec`, `TEMP`, and the per-user `APPDATA` folders where the coding CLIs keep their configuration and credentials. Windows sessions now keep those while still withholding API keys and tokens.
- **[issue-3202] Restarting PortOS no longer marks a running agent "completed" or burns its retry budget** — a restart kills every agent PortOS owns, and the terminal-based ones reported that as a clean finish. The task was recorded as done with nothing but two startup lines to show for it, and the folder holding its work was deleted on the way out. When the task did come back, the restart was counted against it as a failure: three routine restarts were enough to block the task outright, and two in a row left it sitting in a 30-minute cooldown. PortOS now recognizes that it was the one that pulled the plug. An agent cut short by a restart — terminal-based or headless — is recorded as interrupted rather than finished, its working folder is left untouched, and the task returns to the queue immediately, resuming from what the interrupted run left behind with no retry charged and no cooldown. An agent that had already reported its results still completes normally, one you terminated yourself is still recorded as terminated, and agents that genuinely fail on their own are unaffected. Agents still stop when PortOS restarts; keeping them running across one is separate work.
- **[issue-3202] CoS terminal agents now stay alive through a PortOS server restart** — their interactive processes run under the standalone CoS runner, while the web server reconnects to the surviving session, restores its Shell view and status stream, and continues without launching a duplicate. A deliberate full-stack restart still terminates the runner and its agents.
- **[issue-3211] Orphaned agents now close their run history during recovery** — a process that disappeared before normal completion left its run permanently unfinished, with no end time, outcome, transcript size, or usage reconciliation. The recovery sweep now closes that run exactly once before requeuing the task, records PortOS-restart interruptions separately from ordinary failures, and safely handles older agents or missing run data.
- **[issue-3216] Messages pasted into agent terminals now submit reliably** — BTW notes, Shell photo drops, and max-runtime wrap-up prompts use the same repeated-Enter strategy, so a TUI reflow can no longer swallow the only submit keystroke and leave the message stranded.
- **A brief internet outage no longer kills a working CoS agent.** When the machine lost its connection, a running agent's terminal went quiet — it couldn't reach the model — and after a few minutes the idle watchdog mistook that silence for a hung or finished agent and reaped it, throwing away in-progress work. PortOS now checks whether the machine is actually online before reaping an idle agent: while the connection is down, the reap is deferred and the agent is left alone to resume the moment the network returns (with a short grace so it isn't reaped in the instant between reconnecting and picking back up). Genuinely stuck agents on a healthy connection are still reaped on the same schedule as before, and the long absolute run-time ceiling still bounds an agent kept alive through a very long outage.
- **Agents are now told nobody is there to answer them, and a run that stalled on a question says so.** An agent PortOS launches runs unattended, but nothing in its briefing said that — so an agent that hit a multiple-choice question or an approval gate would sit there presenting it to an empty room until the idle watchdog killed the run and discarded the work. One task was retried into the same question three times and filed nothing. Every agent briefing now states that no human is present, to decide for itself and record the assumption rather than ask, and to invoke slash commands in their non-interactive form. When a run does stall this way, the failure is no longer reported as a bare idle-out — PortOS notices the transcript ends on an unanswered prompt and says that's what happened, so the next step is skipping the gate rather than hunting for a stalled provider.
- **An agent killed by a server restart now picks up where it left off instead of starting over.** Restarting PortOS kills every running agent mid-edit, and the task went back in the queue for a brand-new agent that built a fresh worktree from `main` — so hours of in-progress work sat on disk, untouched, while the replacement redid it from scratch. PortOS now records what the interrupted run left behind and hands the retry its actual working directory: its commits, its uncommitted edits, and its untracked files, exactly as they were. The retry is told up front that it's continuing someone else's run and to check `git status`, the commit log, and whether a PR was already opened or merged before writing any code. Work that already landed is still never resumed onto, and if the leftover folder can't be handed over for any reason the retry starts clean rather than failing to start.
## Image generation

- **Test Connection in Image Gen settings now tests the CLI whose tab you're on.** Pressing it from the Grok CLI or Agy CLI tab probed whichever backend was saved as the default instead — so an Agy test answered `codex — codex-cli 0.145.0`, which looked like Agy had somehow resolved to the Codex binary. The button now probes the provider for the open tab (Backend, Tokens, Expose, and Test still probe the saved default backend), and every result is shown only under the tab that asked for it — so a slow probe you left behind can't surface under the provider you switched to.
- **[issue-3186] Agy CLI is now an opt-in image-generation backend.** Users can enable Antigravity in Image Gen settings, select an installed or custom model, and send text-to-image work through its `generate_image` tool with queue progress, cancellation, gallery metadata, cleaner options, and CoS tool registration. Each render runs in an isolated scratch directory and only a signature-verified directed image is imported; image-edit surfaces continue to use an edit-capable backend.
- **Agy's model field is now labeled for what it actually selects, and can be overridden per render.** The Image Gen settings field was labeled "Image model" while listing Gemini agent models, which read as the wrong list being loaded. It isn't: `agy models` is the catalog of *agent* models the CLI's `--model` flag accepts, and that agent is what drives the built-in `generate_image` tool. Agy exposes no knob for the underlying image model — its `generate_image` takes prompt, image name, aspect ratio, and reference paths and nothing else — so there is no `imagen-*` option to offer, and passing one makes agy exit before it generates. The field is now "Default agent model" with that explanation, and the Image Gen page adds an **Agent model** picker so a single queue item can run on a different agent model than the saved default without a settings round-trip. Leaving it blank inherits the Settings value; a pinned model that Google later drops from the catalog falls back to the default instead of failing the render. The retry editor on a failed Agy job now edits that same model field (it was bound to the local model-id field, which Agy never reads).
## Game

- **[issue-3228] Game detail workspaces keep asset blockers and controls in reach.** The compact header and section tabs stay pinned while each panel scrolls independently, blocked rows explain how to recover and link directly to surviving Sprite or Music records, and missing, malformed, and deleted music audio now report distinct causes.
- **[issue-3177] Added a Game studio for assembling managed-app asset bundles.** Create a Game workspace, bind reusable Sprite records and Music tracks, compile an immutable versioned manifest with SHA-256 asset references, and request persisted AI feedback with any configured provider, model, and supported effort. The new `/game/:id` workspace is reachable from Create, Cmd+K, and voice navigation.

A game can be started from its workspace only after the current manifest and all bound asset bytes pass verification.

## SongBook

- **Drum charts now play through a real drum-machine kit, with a punchy kick.** The play-along kit was synthesized from a single generic recipe, and the kick came out weak: its pitch slid from the attack all the way down across its whole (very short) tail, so it never settled on a fundamental and never developed any body — on a phone or laptop speaker it barely registered under the hats. The kit has been rebuilt as three you can choose between from the practice settings: **TR-909** (the new default — attack-forward kick, bright snare crack, tight hats), **TR-808** (deep sub kick with a long tail, thin snare, metallic square-cluster hats), and **Acoustic** (rounder, closer to a studio kit). Every drum now snaps to its pitch in the first few hundredths of a second and then rings out, the way a real drum machine does, and the low drums are saturated so the harmonics carry the kick on small speakers that can't reproduce a 48 Hz fundamental at all — measured, that puts about 9 dB more of the kick through a small-speaker response than the old recipe. The whole kit runs into a soft limiter, so a downbeat stacking kick, crash and metronome no longer clips. Swapping kits applies immediately without stopping playback, and your choice is remembered on that machine.

- **[issue-3222] Drum-chart previews are now audible while you write or import.** The editor and import preview both include the full practice transport, animate the sounding chart's playhead, and keep playing the snapshot captured at Play even as you continue typing; a clear reload notice appears when the draft changes.

- **Drum charts now play the whole song as one continuous, phone-readable strip.** The kit sheet was a vertical stack of per-bar grids — on a phone, two transport rows and a controls row pushed all but a bar and a half below the fold, and reading a groove meant scrolling down between bars. The whole song is now a single horizontal lane that scrolls under a playhead as it plays, with the kit-piece labels frozen in their own column so "which row is the snare" survives scrolling to bar 30, and A−/A+ zooming the grid. The playhead glides off the audio clock instead of hopping between hits, so it keeps moving across rests and through a bar with no hits at all. The transport is split for a phone: play, tempo (with ± steppers), the metronome and a live beat-pulse/bar readout stay visible, while practice speed, count-in and the loop range collapse behind a settings button until there's room for them. The metronome now defaults on and remembers being switched off, and a drum chart no longer shows the vertical autoscroll transport — its rival "play" button that scrolled the page instead of the song.

- **Tap a note on a drum chart to find out what it's asking for.** The kit grid is PortOS's own notation, so there was nowhere to look up what an × with a chevron over it on the crash row actually means. Tapping any note now opens a readout naming the piece, the articulation ("Crash — Accent"), where it falls ("bar 6, count \"2 e\""), how hard it's struck relative to a full stroke, and how to strike that piece. The tapped note is boxed on the sheet so it's clear which one is being described, a near-miss on a tight groove still answers rather than dismissing, and tapping empty grid closes it. A new Legend button lists all six cell characters plus how to play each piece the chart uses, and the sheet takes keyboard focus so ←/→ walk the hits for anyone not using a touchscreen.

- **[issue-3218] Tab sheets now explain their articulation characters.** When an arrangement includes a tab staff, a Legend button defines hammer-ons, pull-offs, slides, bends, releases, vibrato, and muted notes, including how to play each technique. Chord-over-lyrics and plain-text sheets stay uncluttered when that notation is absent.

## Quota burn

- **[issue-3179] Quota-burn no longer spends window budget on runs that never happened** — a scheduled quota-burn run counted against the family's per-window dispatch cap as soon as it was considered, even when it was subsequently skipped and no agent was ever started. Those phantom dispatches ate the budget, so a family configured for e.g. 5 burns per reset window could fire far fewer — and a family capped at 1 could never fire at all, because the skipped run consumed the only slot before the next gate re-read it. A burn is now counted once its agent has actually run, and a burn that is queued or in progress holds its slot in the meantime, so the cap stays accurate without letting a second app or a repeated "Run" overshoot it.
- **[issue-3182] Quota-burn dispatch caps survive agent recovery and server restarts** — when PortOS reaped an orphaned burn or received its completion after restarting, the recovery path skipped the output hook that records the consumed slot. The next tick could then launch another burn beyond the configured window cap. Recovery now runs the same bounded output hook as normal completion, with an exactly-once marker that prevents normal and recovery paths from double-counting the same agent.

## Fixed

- **[issue-3223] Published sprite atlases now expose frame counts uniformly for custom animation tracks.** A consuming game can read a user-authored track's declared frame-count field from both the atlas manifest and its layout sidecar, just as it already could for walk, scanner, and ambient tracks; tracks with no known count remain omitted.
- **Sprite correction notes are no longer ignored on regenerate.** Typing a correction on a sprite re-roll ("hip bag should be on the other leg") and hitting Regenerate produced a render essentially identical to the one you'd just rejected. The note was being sent — it was losing an argument inside the prompt. Every regenerate prompt spends several sentences pinning the render to the attached reference ("keep accessories on the same anatomical side", "treat the turnaround panels as the source of truth"), and the correction was one trailing sentence asking to change exactly that, phrased as an edit to the *attached* image rather than a fix in the image being produced — so the model sided with the bulk of the prompt. Corrections now frame the render up front, before any preservation rule is read, and close it with an explicit override. Verified on the reported case: the note that had left the sprite unchanged now moves the bag on both samples. A blank note still produces a byte-identical blind regenerate on every surface (turnaround, main, the 7 directional anchors, walk, and every animation track including user-defined ones).
- **Sprite reference reopen warnings now name the animations you actually have, instead of assuming a "scanner".** Reopening a locked main reference asked "Reopen the main reference and its south walk/scanner?" — but `scanner` stopped being a built-in some releases ago and is now just a seeded row you can retune or delete like any other animation type. So the warning was wrong in both directions: if you'd deleted the scanner it named an animation you don't have, and if you'd authored your own directional animation it never mentioned the approvals it was about to drop. The main-reference and turnaround warnings now list this character's own directional animation types by name (non-directional ones aren't affected by a reference reopen, so they're correctly left out), falling back to the plain word "animations" when there are none to name. Two toasts were under-reporting the same way: unlocking a single directional anchor only mentioned the walk it reopened, and unlocking the turnaround counted only reopened walks — both now cover every animation type the reopen actually dropped.
- **The Chief of Staff 3D avatar no longer sometimes renders as an empty glowing ring.** The Cyber Muse and Mini-Character avatars share one loaded 3D model with the CyberCity player avatar, and letting the 3D engine free that model's data when one avatar left the screen left the next one pointing at freed data — so it drew nothing, leaving just the halo ring behind it (which looked like a lone SVG circle). This happened intermittently after switching avatar styles, changing tabs, or visiting CyberCity. Each avatar now keeps the shared model intact when it unmounts, so it reloads cleanly every time.
- **Music Video analysis now finds the beat in guitar-led songs and shows its evidence.** The offline detector uses spectral change instead of whole-track loudness changes, with later-window consensus for quiet or rubato intros. The director timeline now includes a full-song energy waveform, beat/downbeat markers, section energy, time rulers, a clickable overview, and an explicit 4/4-grid assumption instead of presenting an empty “beat-quantized” strip when the cached analysis contains no visible musical information.
- **Music Video final renders now honor the authored song timeline.** Scene clips loop when their generated source is shorter than the beat-aligned cut, so an arrangement can cover the full track instead of being silently truncated to each model's native clip length.
- **The task form's Screenshot and Attach buttons work again — a stuck notification was eating the clicks.** A notice that never goes away (the "Install out of sync" warning, "Update available", "New build available") parks in the bottom-right corner, and on a desktop window it landed on top of the Chief of Staff task form and silently absorbed every click meant for the buttons underneath. They did nothing at all — no file picker, no error, nothing in the browser console — which is why it read as a broken button rather than something covering one, and why the same page still worked on a phone, where the layout puts those buttons elsewhere. On a 1280×720 window the notice covered a 520×86px block starting at the exact pixel the Attach button begins. Notices that never dismiss themselves now fold into a small badge in the corner after 8 seconds (1600px², clear of the page); clicking the badge brings the message back, and it stays open while you hover it or use its buttons. Toasts with a set lifetime — including the manuscript Undo prompt — are untouched.
- **CoS agent PRs no longer open with TUI startup noise as their description.** A PR that PortOS opened for a Codex/Antigravity/OpenCode agent led with the session's own lifecycle log — `📟 TUI session started: … (codex …)`, `💡 Open the Shell tab…`, `📟 Prompt pasted…` — before getting to what the agent actually did. The PR description now starts at the agent's completion summary and drops PortOS's status lines, along with the trailing `## Branch` / `## PR` section that only repeats what the PR page already shows.
- **Review Hub success-rate alerts now require recent runs.** Low lifetime rates for task types that have been idle no longer appear as current health anomalies; alerts are shown only after enough runs occur in the rolling 30-day performance window.
- **Malware scan reports now open inside PortOS.** Scan links from Brain, the Review Hub, and completed CoS agents render the markdown in a mobile-friendly PortOS page instead of navigating a Home Screen install to the raw `.md` API response. Brain Links also has a Scan Reports filter, so clean and caution results are just as discoverable as dangerous findings.
- **Malware scan report pages scroll again.** Opening a scan report from a Brain link card showed the top of the report and nothing else — the page couldn't be scrolled, so anything past the first screenful was unreachable. Long reports now scroll normally on desktop and mobile.
- **Branch reconciler no longer hands long-lived shared branches to the coordinator agent.** `gh-pages` (the GitHub Pages publishing branch) is now protected alongside `main`/`master`/`dev`/`develop`/`release`, so the scheduled `branch-reconcile` task never tries to "open a PR" merging it into the default branch (which would break the published site). The reconciler now reuses the single canonical `PROTECTED_BRANCHES` set in `server/lib/gitArgs.js` instead of its own narrower list, so it also picks up `dev`/`develop` protection.

## Changed

- **Chief of Staff feedback now captures why an agent helped or missed the mark.** Add detail to positive, negative, or neutral ratings so future CoS learning has the context needed to improve.

- **Branch reconciler prioritizes recognized work branches.** The in-flight set handed to the coordinator agent is now ordered by branch prefix — `claim/`, `cos/`, `next/`, `feature/`, `fix/`, and other conventional prefixes are reconciled ahead of unrecognized/ad-hoc branches — so a bounded run spends its budget on real deliverables first. Both `/` and `-` separators match.

- **The Catalog page is usable on a phone.** The toolbar used to run off the side of the screen and the filter dropdowns each claimed a fixed width they didn't have room for. Now the view toggle spans the width as a segmented Grid/Albums control with the three actions split evenly beneath it, search sits directly under the header so it's reachable without scrolling, the type chips stay on one swipeable row instead of stacking three rows deep, and the Universe/Series/Tag dropdowns lay out two-up. The selection bar stacks its count above three equal-width buttons, and its "Remix into…" / "Add to universe/series…" menus now span the bar instead of opening off-screen. Delete and select targets on each card are bigger, and long album subtitles drop below the title rather than squeezing it. Confirming a card delete now shows a band across the top of the card naming the ingredient — `Delete "Echo Saint"?` — instead of an unlabeled prompt tucked in the corner, which on a phone left barely enough room for the name beside it. That one is visible at every width; the rest of the layout is unchanged on a desktop-width window.

## AI providers

- **[issue-3194] Ask and image captioning now work on a local OpenCode provider.** If you pointed Ask Yourself or vision captioning at an OpenCode provider backed by Ollama, the run failed with the model reported as "not valid" — OpenCode has to be told which local models exist before it will accept one, and only the agent and Run Prompt paths were doing that. Every path that starts a coding CLI now declares them the same way, so the model you picked is accepted wherever you use it.

## Internal

- **[issue-3194] Consolidated the AI-CLI child-environment composition.** Ten spawn sites each rebuilt the same environment tuple by hand (provider env vars, the OpenCode declared-models map, the working-directory pin, the nested-session strip, and the pm2 guard shim for agents), so every environment-level fix had to sweep all ten and a missed site failed silently — which is exactly what happened to the OpenCode fix once already. `buildCliChildEnv` now owns the full child env and `composeProviderEnv` the ordered layers for sites that hand off a partial env, both preserving each site's original precedence. A discovery-based test fails when a new spawn site composes the environment by hand instead of routing through them.
