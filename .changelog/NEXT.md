## Added

- CoS now notices when a scheduled task (the overnight branch-reconcile loop) finishes the same work over and over in short-lived agent runs. It parks a looping coordinator so it stops burning quota and keeps the per-run duration signal local for a future Layered Intelligence run to assess and, only when justified, turn into a concrete planned fix.
- Git submodules are now managed per app instead of on one global Dev Tools page. Any managed app whose repo has a `.gitmodules` gets a Submodules tab showing each submodule against its remote, so PortOS's own bundled slashdo is maintained from the PortOS app page alongside its git, processes and update controls. Updating a submodule can now also commit the pointer bump for you: leave "Commit the pointer bump" on and the update stages just that submodule and commits it on the repo's default branch. It refuses to commit — and says why — when the repo is checked out on some other branch, so the bump can't land in the middle of unrelated work. The old `/devtools/submodules` link redirects to PortOS's own tab.
- Quota Burn steps can now be marked **Run once**, so a burn plan can be a one-shot series instead of a rotation that repeats forever. A plan is walked lap after lap until a quota gate closes, which is right for a standing audit and wrong for work that only needs doing once — that work was simply re-done every lap for as long as the window had quota left. A step marked Run once records its dispatch, drops out of the rotation, and shows when it ran, with a ↺ Re-arm on the row (and Re-arm all on the plan) to put it back. Re-arming spends nothing; the next cycle still faces every gate. Existing plans are unaffected: steps repeat by default, exactly as before. A plan whose steps have all run also stops paying for the multi-second provider quota scrape every interval, and reports "every enabled job has already run once" rather than looking misconfigured.
- The Usage page can now record what you pay each month for your AI subscriptions (Claude, Codex, Antigravity, Grok) and shows what those plans saved against the estimated API cost. Each plan's price is prorated across whatever report window is selected, so both sides of the comparison cover the same days, and every plan gets its own row: monthly price, cost for this window, the API-rate cost its usage ran up, and the difference. Usage no subscription covers — pay-as-you-go API providers and pre-breakdown legacy rows — is reported separately instead of being credited to a plan.
- Series Autopilot can now run every stage on one provider and model. Picking a provider for a run only ever set a *soft* default, so any stage carrying its own pin on the Prompts page kept its own provider, model or reasoning effort — which meant "run this series on Sol" quietly left script verification (pinned to Codex in the shipped stage config) and every other pinned stage where it was. A new "Use this provider and model for every stage" option under Autopilot → Options overrides those pins for the whole run, including the judge pin, and is saved as a default for future runs. Scheduled runs get the same checkbox next to their provider picker. Stage *tiers* (quick/coding/heavy) still resolve against whichever provider ends up running, and the separate judge and per-stage routes in the same panel still win — the option removes the stage-config pins from the comparison, not your own choices. Leaving it off keeps today's behaviour exactly.

## Fixed

- Turning on scheduled backups now actually schedules them. The daily backup cron was registered once at server start, so if backups were off — or no destination folder was set — when PortOS booted, enabling them in Backup settings did nothing until the server was restarted, and no backup ever ran. The schedule is now kept in sync with your settings: enabling backups or picking a destination registers it immediately, editing the schedule re-registers it, and turning backups off cancels it.
- Canon entry cards in a universe bible are usable on a phone again. The card's icon action strip sat as a full-height column beside the entry's content, so on a phone it squeezed the description box and every collapsible editor under it to about a third of the card — the description was clipped after a few words and the "Reveal timing" and "Outfits" headers wrapped into tall centered stacks. The action strip now shares the entry's title row and the content spans the full card width beneath it. Long entry names wrap instead of being cut off mid-word (variation and reference-board rows on the same page too), a collapsed "Outfits" header clips its outfit list to one line, and the character colour rows leave their hex field enough room for the description beside it.
- Wrapped labels inside buttons no longer render as a centered ragged stack. Browsers center button text by default, which is invisible while a label fits on one line and only shows up once it wraps — so it surfaced on phones, in section headers across the app, and not on desktop. Buttons that lay their contents out in a row now read left-aligned unless they explicitly ask to be centered.
- Voice dictation into the Shell terminal no longer garbles what you said. Apple dictation streams progressively refined guesses and rewrites what it already typed ("determin" → "determine" → "determines"); the terminal forwarded every insertion but none of the matching deletions, so a dictated sentence arrived at the prompt as an accumulating pile-up ("ddedeterdetermindeterminedetermines if any code…"). Dictation edits are now translated into the deletions and insertions a terminal understands, so the prompt shows the sentence you dictated.
- The Branch & PR Reconciliation task no longer re-launches itself indefinitely when branches are left behind. Its drain re-issued itself through the same queue a human "Run Now" uses, and that queue's handler cleared the convergence state on every hop — so the "nothing changed, stop" brake was wiped before it could ever apply, and the task spawned roughly forty coordinator agents in one night against the same two branches. Automated re-issues now inherit that state, so an unchanged branch set parks after one cycle as designed.
- Branch reconciliation now leaves branches alone while their session is still running. A live agent's (or live `/claim`'s) branch with a clean worktree and an open PR was treated as work to finish, so the reconciler raced the running session's commits — and every push it made counted as "progress" that earned another reconciliation run. Those branches are now reported and skipped, and a reconcile whose only remaining branches are live is finished rather than retried. Ownership is read from the branch name as well as the worktree, so an agent that has already cleaned up its worktree but is still working is still recognized.
- Automated reconciliation runs no longer raise a "nothing to do" notification. Only a run you started by hand reports back, so a healthy overnight drain converges quietly instead of leaving a pile of notifications.
- Branch reconciliation no longer mistakes GitHub's mergeability lag for progress. GitHub answers `UNKNOWN` until it finishes computing whether a PR can merge, so consecutive checks of a completely unchanged PR looked like a branch advancing.
- Both reconciliation tasks (branches and stale issues) now stop after a bounded number of back-to-back runs even when each run does make some progress, and wait for their next scheduled check. Nothing is dropped — the remaining work is found again on that check.
- A task that has parked itself no longer gets restarted anyway the moment its previous run finishes. Parking is what stops a drain-until-done task from running all night, but it was only ever read by the scheduled path — the automatic "keep draining" restart never checked it, so a task could park and be relaunched on the very next completion, indefinitely. That restart now honors the park, and the bounded back-to-back run limit applies to every drain-until-done task rather than only the two reconciliation ones. The claim-and-ship task types are deliberately left unlimited so a healthy overnight run is not throttled, and pressing "Run Now" is unaffected.
- Tapping the notifications bell on a phone now opens a panel that stays on screen. It was anchored to the bell — which sits mid-screen in the sidebar — so the panel ran off the right edge, clipping notification titles and putting every per-item dismiss button and the mark-all/clear-all controls out of reach with nothing to scroll to them.
- The notification panel's "+N more notifications" line is now a "Show N more" button, so the notifications past the first ten can be read and dismissed instead of being permanently unreachable.
- Notification dismiss and "Mark read" buttons are now full-size, always-visible tap targets on touch devices — they were sized to their bare icon, and the dismiss button was only revealed on hover, which a phone has no way to do.
- The notification panel now closes on Escape, and long notification descriptions wrap to two lines instead of being cut off mid-word.
- Agent tasks run by a provider without slash commands (grok, OpenCode, codex, antigravity) now actually get their pull request merged. PortOS drives the whole push/PR/merge lifecycle for those providers via a follow-up task — and that task was written to the task file with `app: null`, which read back as an app named "null" and blocked the follow-up before it started. The PR, its branch, and its worktree were then left behind with nothing in the system that would ever land them.
- Merge follow-ups already stranded that way are revived on upgrade, so the pull requests they left open finally land. Their blocking reason was exempt from both the failed-task reaper and the automatic retry, so they would otherwise have sat blocked forever.
- Task metadata that has no value is no longer written to the task file at all. Any unset field previously became the literal word "null", which every reader then saw as a real value — the same class of bug as the blocked merge follow-up above. Task files an older version already wrote are repaired on read.
- Blocking a task that exists to merge a pull request now raises a notification naming that PR, so it can be landed by hand instead of going unnoticed. This covers every way a task can get blocked, not just the one fixed above.
- An Antigravity (agy) agent no longer sits doing nothing on "Verifying your account…" until it is reaped. PortOS already held such a run open for a grace window instead of killing it, but that wait could never work: the banner is agy rejecting the submission — the prompt is discarded and the composer goes back to empty and idle — so nothing was ever in flight for the wait to notice, and the window's only possible outcome was to expire. PortOS now re-sends the prompt every 20 seconds for the length of the window (which is what the banner itself asks for), so a verification that clears — the normal case, in seconds — gets the work done on the provider you picked instead of failing over.
- Fixed the reason those runs hung for their full idle timeout rather than failing over at all. PortOS decided the provider had come back if it saw agy's `esc to cancel` footer — but agy shows that same footer for its slash-command menu, so merely opening the menu in a parked session (a `/usage` check, or a glance from the Shell page) counted as recovery. That permanently disarmed both the retry and the fail-over, and the run was finally recorded as "idle with no changes". Recovery is now judged only on chrome agy paints while a request is genuinely running.
- A series' pinned image backend now actually renders its comic pages and covers. The pin was saved on the series and honoured by first-pass portraits, but the comic stage sent the install-wide default as an explicit choice — which outranks any pin — so a series pinned to one backend quietly rendered every page and cover on another. The Pipeline visuals default from Settings → Image Gen now applies to these renders too, and a pin naming a backend you have since turned off falls back instead of failing the render.
- Typing on the Shell page no longer doubles capital letters and spaces. `Hi There` arrived at the shell — or at a watched agent TUI — as `HHii  TThere`, which made typing a message to a running agent unusable. The terminal forwards most printable keys on keydown and cancels the event there, but hands capitals and space to the browser's keypress default action, which then also fires an input event for the same character. The dictation bridge (which reads those input events to keep voice dictation from garbling) was translating that second event into a second keystroke; it now recognizes an insertion the keypress path already sent and leaves it alone. Voice dictation and soft-keyboard input, which arrive with no keypress behind them, are unaffected.

- Two CoS agents running without a worktree can no longer steal each other's completion. Agents whose task needs no code change (the issue-filing and reasoning types) all run in the primary checkout, and every one of them wrote its done-signal to the same `.agent-done` file — so with two running at once the second overwrote the first's summary, and each run's 2-second poll finalized on whichever sentinel happened to be there, attributing one agent's result to the other and killing a session that was still working. The sentinel is now named per agent instance (`.agent-done-<agentId>`), resolved from one helper by every side that touches it — the path written into the agent's prompt, the 2-second poll, the durable runner's watch, the CLI exit check, the structured-payload read, and the worktree-cleanup ignore — so a run reads, cleans up, and reports only its own. A Layered Intelligence reasoning run, where that file *is* the deliverable, was also being handed two different filenames in one prompt; its instructions now defer to the sentinel path the briefing gives it. The one behaviour to know about on upgrade: an agent still mid-run when the server restarts was told the old shared name, so it finalizes through its normal idle/exit path rather than the sentinel poll.

## Changed

- Adding an app no longer writes a PM2 config into the project on its own. Importing a directory ran the PM2 standardizer the instant detection finished — dropping an `ecosystem.config.cjs` into the repo, commenting the ports out of its `.env` and Vite config, and cutting a git backup branch — before you had even saved the app. Only iOS/macOS/Swift/Xcode projects were exempt, so Docker stacks, Python services, static sites, and anything else you start another way all got a PM2 config they will never use, plus an LLM call nobody asked for. Standardizing is now a button in the Add App wizard that says what it will rewrite, and it is still available later from the Apps list. The wizard also shows the standardizer's live per-step detail while it runs (including the "no git repository, backup skipped" case) instead of one undifferentiated row.
- Standardizing an app is now refused server-side for apps PortOS never runs under PM2, and for PortOS itself. The rule previously lived only in which buttons happened to render, so the socket and HTTP entry points would happily standardize an iOS app — or rewrite PortOS's own `ecosystem.config.cjs`, the canonical source of its port map, from an LLM analysis. The Standardize button on an app's Overview tab is now hidden for PortOS too, matching the Archive button beside it.

- A behaviour-preserving refactor pass tidied several long-standing hot spots without changing what PortOS does. `spawnTuiAgent`'s paste/retry/max-runtime machinery moved into its own controller instead of sharing a ~1400-line function's mutable scope; `agentCompletion` stopped importing `getConfig` from `cos.js`, which was the closing edge of ~82 circular import chains; three inlined bodies in the series-autopilot dispatcher moved out to `arcSteps.js` alongside its sibling step runners; Layout's 85-line full-width-route boolean, ImageGen's mode-label ternary and peerSync's 15-branch lister ladder became lookup tables; the daily/weekly/custom schedule cases collapsed to one shared interval evaluation; `server/index.js` and `Browser.jsx` now use the canonical `PORTS.API` and `formatDurationMs` instead of local copies; and a batch of dead imports was removed. The full test suite passes unmodified — no test file was edited — so return values, side effects, error messages and public API shapes are all unchanged.
- The fork-aware self-update flow is now documented on its own page (`docs/SELF_UPDATE.md`) and indexed in the docs README. It explains why release polling always queries upstream while the update itself pulls from your own origin, what the `FORK_SYNC_REQUIRED` and `FORK_DIVERGED` responses mean, and what each of the three fork-specific update buttons does — previously this only existed as a terse note in the repo's agent instructions.
- The README now matches what PortOS actually is. Its feature list had drifted behind roughly a year of surfaces — Sprites, Game asset binding, the 3D image-to-mesh page, Authors, Story Builder, LoRA training, the Pipeline's editorial/continuity/voice-fingerprint checks, the Privacy Center (vault, organizations, change-of-address, data brokers), the activity timeline, SongBook, iMessage/Signal/X, Workspaces, Flows, the local-LLM playground, and the public API surface were all missing. Several stated facts were also wrong: React 18 (it's 19), 117 curated genome markers (116), six agent skill templates (seven), five POST domains (six — the whole Cognitive domain was unlisted), a provider roster missing Grok Build, Cursor Agent and OpenCode, and a contributing note claiming PortOS has "no auth" when an optional instance password has shipped for some time.
- The setup scripts now require Node 22 instead of 18. Vite 8 needs ^20.19 || >=22.12, so a v18 machine passed the version gate and then failed several minutes later at the client build with a much less obvious error. The README's stated requirement was updated to match.
- Notification panel placement now goes through the shared popover-positioning hook that the theme switcher beside it already used, so it clamps into the viewport and flips above/below on its own instead of relying on hand-written positioning.
- The Code Review Defaults panel now names every CLI reviewer in its help text, generated from the reviewer roster itself — the sentence used to spell them out by hand and fell behind twice as new reviewers shipped, telling users their CLI reviewers ran a different way than they do.
- The remaining trigger-anchored dropdowns — "Run on App" on a scheduled task, and the Share and Sync buttons on series and universe cards — now use the same shared popover-positioning hook as the notification panel. "Run on App" opened a panel pinned to its button's left edge that merely got narrower on a phone rather than moving, so it ran off the right edge; the Share and Sync menus always opened downward even with no room below. All three now clamp into the viewport, flip when there is no room, and stay attached to their button as the page scrolls.
- The theme switcher, the media collection picker, and the Shell photo composer now dismiss through the shared click-outside hook instead of three private copies of the same two-ref check, so the rule that a portaled panel counts as "inside" its own trigger lives in one place. Escape still closes each of them.
- Collapsible section headers in the canon cards, the character detail editor, and the digital-twin interview analysis card now announce their open/closed state to a screen reader. They were five separate hand-rolled copies of the same header, none of which reported that state, and all five now share one primitive so a layout fix lands in one place instead of three.
- The memory list and timeline endpoints now validate their query strings against the Zod schemas that were written for them. Both handlers had been hand-parsing `req.query`, so the declared bounds went unenforced: an unknown memory type, a garbled `limit`, or a nonsense date range was quietly accepted and passed to the database. Both schemas now also accept the comma-separated, string-valued form a query string actually arrives in, and the list `limit` ceiling is 500 — the bound the route has always enforced in practice — rather than the 100 its schema claimed. The timeline endpoint also finally honours an `appId` filter, which both of its backends have always supported but the hand-written parsing never passed along.
- Agents run on an API provider (LM Studio, raw OpenAI/Anthropic — anything with no native filesystem tools) now receive the per-directory `CLAUDE.md` files too, not just the global and repo-root ones. Those agents read nothing off disk on their own, so a convention that lived in `server/CLAUDE.md` or `client/src/CLAUDE.md` reached them as a pointer with no contents — which is how relocating a backup rsync-exclude rule out of the root file silently removed a data-loss guard from that whole class of agent. Nested files are now discovered under the workspace and spliced in after the root one, each labeled with its repo-relative path, bounded to 10 files and 5 levels deep and skipping vendored, generated, and runtime trees.
- The Node version PortOS requires is now written down in exactly one place and checked before anything slow runs. The floor was copied into five sites that could drift apart — both setup scripts, `.nvmrc`, the CI workflows and the README — while the install path the README actually documents (`npm run setup`, `npm start`) checked none of them, so an unsupported Node installed happily for several minutes and then failed inside Vite with an error that never named the cause. `scripts/checkNodeVersion.js` now owns the number (22.12), runs first in the root `setup`, `start` and `dev` scripts so an old Node fails in the first second, and a drift test holds the other sites to it — the shell gates and the README to the floor exactly, `.nvmrc` and CI to at-or-above it, since running CI on 24 while supporting 22.12 is a preference rather than a mistake. All four `package.json` files now declare `engines` as well.
- The Pipeline's Reverse Outline map now keeps the selected scene in the URL (`?scene=<id>`) instead of component state, so the open scene detail survives a reload and can be linked to or shared. A stale id — after regenerating the outline, say — falls back to the "click a marker" placeholder rather than a blank card, and regenerating clears the selection outright.
- The six "file too large" toasts — album covers, artist portraits, tracks, author headshots, reference audio and OpenClaw attachments — now render their size cap through the shared `formatBytes` helper instead of each dividing by 1024 twice and gluing on "MB". The rendered text gains a space before the unit (`12 MB` rather than `12MB`), which is what the rest of PortOS already shows and what the reference-audio toast already read. The OpenClaw combined-attachment message picked up the same treatment for its decoded-size estimate, so the two limits it can report no longer print their units two different ways.
- The post-restart agent-recovery path is now its own function instead of a 65-line branch inlined at the top of `handleAgentCompletion`, so a change to either it or the live in-memory completion path no longer means reading past the other. The pause guard that path sits behind — the one keeping a stray completion event from cleaning the worktree out from under a later resume — is now pinned by tests that call the real function rather than by a source-text assertion that broke the moment the code moved.
- Every inline `new Date(x).toLocaleDateString()` / `.toLocaleTimeString()` in the client — roughly seventy across fifty components, from the calendar views and CyberCity HUD to the CoS tabs, goals, media queue and app-update panels — now routes through `client/src/utils/formatters.js`, so a change to how PortOS renders a date is one edit rather than fifty. The helper set grew to cover the shapes that were being spelled out by hand (`formatDateNumeric`, `formatTimeOfDaySeconds`, `formatMonthDay`, `formatMonthYear`, `formatWeekdayShort`, `formatWeekdayDate`, `formatWeekdayTime`), and `formatClockTime` gained `seconds` / `hour12` options instead of a second copy of itself. Two long-standing paper cuts go with it: a bare `YYYY-MM-DD` is now anchored at local midnight everywhere (a plain `new Date('2026-03-05')` is UTC midnight and renders as the 4th anywhere west of Greenwich — call sites used to fix this by hand, and the ones that forgot showed the wrong day), and a missing or malformed timestamp renders a caller-chosen fallback instead of the literal text "Invalid Date" — including the calendar event-detail formatter, which had ended up guarding its all-day branch but not its timed one.
- The ~460-line Sprite Manager block in `server/lib/validation.js` now lives in its own `server/lib/spriteValidation.js`, matching the eleven other per-domain validation files. A straight lift wasn't possible: the block leans on four fragments (`recordRenderPinFields`, `cloudModelIdString`, `grokVideoDurationSchema`, `isSafeSubdirFilter`) that music video, universe builder, series, video gen and backup also use, and a domain file can't read them back out of `validation.js` — ESM hoists its `export * from` re-exports, so the read lands in the temporal dead zone. Those four moved to a new leaf `server/lib/sharedSchemas.js` first, with `validation.js` still re-exporting them, so every existing deep import keeps working unchanged.
- The TUI runner's response-file tests no longer fail at random on a busy machine. They drive the runner's one-second size-stability window with fake timers, but the polls behind that window read the response file from real disk — and a real read finishes on Node's threadpool, which advancing fake timers does not wait for. Under load a poll's read could land after the test had already moved on, so the run took the timeout or fallback path and the failure looked like a regression in whatever diff happened to be under test. Those five tests now serve the response file from memory, so every read settles as a microtask the timer advance always drains, and the assertions are unchanged.
- The unused `toolUseLocalModelFilter` export was removed from the client's provider helpers. It offered to hide non-tool-capable local models from a picker, but nothing ever called it, and the approach it represented was already settled the other way: agent and coding pickers annotate each option (`🔧 tool use` / `⚠ no known tool use`) and warn below the select rather than filtering, because the underlying heuristic is a positive allowlist — a non-match means "not a recognized tool-caller", not a proven negative, so filtering would make a newer tool-capable family unselectable. The rationale now lives on the annotation helper that survived.
- Deleting or uploading a SongBook attachment no longer crashes when the attachment presence lookup failed on page load. That failure parks the attachment state on a `'failed'` sentinel string so the synced list still renders with presence unknown, but both mutation handlers treated it as an array: the delete handler called `.find()` on it and threw `TypeError: prev.find is not a function`, leaving the row on screen, and the upload handler spread the string into six single-character rows. Both now check for an array first, falling back to the record's own synced list on upload and leaving presence genuinely unknown on delete rather than stamping a false "not on this machine" pill.
- Uploading several SongBook attachments at once no longer stops at the first failure. The upload loop awaited each file without catching, so one rejected read or a single server error broke out of the loop: the remaining files in the selection were never attempted, and the one generic "Upload failed" toast gave no clue which file failed or that anything had been skipped. Each file's read-and-upload now catches on its own, toasting a message that names the file, and the batch continues so the successful files still land.
- Keyboard-shortcut hints across the client now render the right modifier for the machine they're on. `client/src/utils/platform.js` exports a `modKey` (`⌘` / `Ctrl`) label, but only the command palette and the keyboard-help sheet read it — five other hints hardcoded a glyph instead: the 404 page and the Ask composer advertised `⌘K` / `⌘/Ctrl + Enter` to Windows and Linux users, the OpenClaw composer printed both forms side by side, the Writers Room save button's tooltip said `Ctrl/Cmd+S`, and the digital-twin enrichment prompt said `Ctrl+Enter` on a Mac. All five now read `modKey`, which prefers `navigator.userAgentData.platform` over the deprecated `navigator.platform` and degrades to non-Mac when neither exists — behaviour the module now has tests for.
- Leaving the SongBook editor with unsaved edits now asks first. The editor holds every change — sheet text, practice notes, metadata — in an in-memory draft until an explicit Save, so clicking View, following the "All songs" link, or closing the tab dropped the work silently. The page now compares the draft against the saved song (numerically for capo, since the number input hands back a string and retyping the stored value would otherwise read as an edit) and defers those exits behind an inline "Discard your unsaved changes?" band under the header, with Discard resetting the draft and Keep editing leaving it intact; a tab close or reload arms the browser's own prompt. Saving clears an armed confirm, since the draft is no longer dirty.
- `client/src/utils/cityChronotype.js` now exports only `computeChronotypeEnergy`. Its six internal pieces — the two range constants, the neutral-modifier sentinel, and the `parseHour` / `computeEnergy` / `energyModifiers` steps — were exported purely so the unit tests could reach them, but the utils barrel re-exports every module flat, so generic names like `parseHour` and `computeEnergy` sat in the shared namespace waiting to collide with a future module. The tests now drive every one of those behaviors through the public entry point (an unparseable or out-of-range peak window yields the neutral no-op; the `:30` half-hour still lands the peak center at 11.25), plus one assertion that the module's export list stays a single name.
- An AI generate or refine started in the Story Builder now survives clicking another step on the left rail. The step panel is keyed by the active step, so navigating away unmounted it — which tore down the SSE progress stream and threw away the completion handlers, leaving the run to finish on the server with no phase updates, no success or failure toast, and a stale view until a manual refresh. Each run's stream, phase and handlers now live in a provider mounted above the rail (`client/src/hooks/useStoryStepRuns.jsx`), one slot per step id, so runs on different steps can be in flight at once and the panel picks its own run back up — including which character a refine targets — when the user navigates back to it.
- `docs/SELF_UPDATE.md` now documents that `update.sh` / `update.ps1` check out `main` before pulling, stashing a dirty working tree first so the checkout can proceed. The doc described only the `git pull --rebase --autostash`, so anyone running an in-app or CLI update from a feature branch or a detached HEAD was surprised to find their checkout moved to `main` with their work parked in `git stash` — the scripts print the restore commands on completion, but nothing said so up front.
- The Vite dev server example in `docs/PM2.md` no longer tells you to point PM2 at `node_modules/.bin/vite`. PM2 resolves a relative `script` against its own working directory rather than the app's `cwd`, and the `.bin` entry itself varies by platform and package manager (symlink, `.cmd`/`.ps1` wrapper, generated shell script), none of which the Node interpreter launches uniformly — so a config copy-pasted from the doc crashed on startup. Both the standalone snippet and the complete monorepo example now use the absolute `path.join(__dirname, 'client', 'node_modules', 'vite', 'bin', 'vite.js')` form that PortOS's own `portos-ui` app has always used, with a note explaining why.
- A failed URL import in the SongBook importer no longer leaves the form looking untouched. The error had only a transient toast behind it, so once it faded the URL still sat in the input with no preview, no explanation, and a Save button that answered with the unrelated "Nothing to save — paste or fetch a tab first". The From URL tab now keeps an inline alert under the input naming the failure with a Retry button next to it, clears that alert as soon as the URL is edited, and drops any previously fetched draft (and the title/artist it auto-filled) so a failed fetch can't leave the earlier song previewed under a URL that never loaded. The disabled Save button now says why it's disabled instead of waiting for the click.
