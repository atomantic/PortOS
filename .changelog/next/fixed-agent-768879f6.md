- **Windows console windows no longer flash and steal focus.** A process with no console of its own — every PortOS app, since they are all PM2 forks — makes Windows allocate a brand-new console for any console child it spawns (`git`, `gh`, `psql`, `ffmpeg`, `where`, `taskkill`). Under the Windows 11 default terminal setting that allocation is handed to Windows Terminal over COM, which starts `OpenConsole.exe -Embedding` plus a terminal window that grabs foreground focus and dies with the child; at PortOS's background spawn rate that is a steady stream of unusable windows stealing keystrokes. Server runtime code now imports `server/lib/childProcess.js` instead of `child_process` — a drop-in wrapper that defaults `windowsHide: true` (`CREATE_NO_WINDOW`) on every `spawn`/`spawnSync`/`fork`/`exec`/`execSync`/`execFile`/`execFileSync`, keeping `promisify.custom` so `promisify(execFile)` still resolves to `{ stdout, stderr }`, and honoring an explicit `windowsHide: false`. 84 files migrated. `childProcess.guards.test.js` now fails the build on a direct `child_process` import, on an aiToolkit spawn without inline `windowsHide`, and on `pm2` invoked through a shell — the same bug was swept away by hand in v1.5.x and v1.6.7 and regressed both times. Also routed the two `shell: true` pm2 calls back through `execPm2` (`cosHealthMonitor.js` auto-restart, `browserService.js` start/stop/restart/jlist/logs), dropping the `cmd.exe -> pm2.cmd -> node` hops and the PATH ambiguity of resolving a bare `pm2` through a shell, and fixed the missing `windowsHide` on the aiToolkit CLI probes and on `browser/server.js`. New `npm run fix:windows-console` points the machine's default terminal at the classic console host, which stops the handoff for every app on the box, not just PortOS. Background: `docs/WINDOWS_CONSOLE.md`.
