# Release v2.102.0 - Storyboard Sidekick

Released: 2026-10-23

## Highlights

- **Storyboards become productions:** Start a Video draft from a board, fit its panels to a song, and keep music-video shots linked to their panel art and edits.
- **More ways to create with Runway:** Generate stills with named canon references, choose Seedream 5 Pro or Lite, edit existing video, and create character performances.
- **A more useful GitHub inbox:** Act directly on suggestions, automate done, mute, or agent actions by account and organization, and review waiting deployments in place.
- **Cast across ages and eras:** Give characters, environments, and objects alternate forms, with their own sheets and reference images.
- **Recoverable FableLoom shot planning:** Scene-by-scene work checkpoints progress, survives disconnected requests, and keeps completed work when a later stage fails.
- **Clearer usage costs:** Explore a stacked cost chart with date ranges and pinned days, including locally recorded Claude Code and Codex sessions started outside PortOS.
- **Lighter everyday browsing:** Smaller collection covers, compact history and conflict lists, shared background reads, and more efficient catalog queries reduce repeated work and downloads.
- **Safer records and host access:** Imports and overlapping saves preserve existing data, while more operations that launch host work require operator authority.

## Added

- Storyboards can create a linked Video draft with a preview of its exact shots, durations, and cast before any generation starts.
- Music videos can link an existing storyboard or build one from their shots, then fit panels to song sections, lyrics, and beats.
- Linked shots show changed or deleted panels, offer an explicit Update action, and can send a selected still back as panel art.
- Storyboard panel art can guide a fitted shot's composition through a visible reference choice.
- Runway offers still-image generation with tagged canon references, ordered Seedream 5 references, video editing, and character-performance workflows.
- GitHub automation rules support account, organization, repository, and notification-kind scopes, with a preview of matching threads and an apply-now action.
- GitHub deployment approvals show the waiting environments and let the operator approve or reject them from the inbox.
- GitHub accounts can disable notification processing on an instance, and Enterprise accounts can explicitly opt into agents and instance-wide author trust.
- Casting, Environments, and Objects support alternate ages, eras, and looks, including form-specific sheets and reference filtering.
- The Pull Requests tab can guide an operator through repairing a GitHub login's missing OAuth scope.

## Changed

- GitHub inbox suggestions are actionable buttons; read threads move to Handled, and finished or read threads can be cleared together.
- CI activity can be handled by a built-in automation rule, while security alerts, suspect threads, invitations, and deployment approvals retain their protected handling.
- Runway model choices and supported controls come from a cached capability catalog with manual refresh and a saved fallback.
- The usage chart groups costs by subscription, adds a dollar axis and keyboard-accessible day pins, and remembers the selected date range.
- Catalog cards and media-collection covers use smaller thumbnails, and large video histories, task lists, and sharing-conflict lists load bounded summaries.
- Setup highlights degraded capabilities first, and Dev Tools and casting pages use consistent headers and navigation.
- Ask conversations, peer setup controls, song titles, and empty states work more comfortably on small screens and touch devices.
- Local test concurrency follows Chief of Staff settings, and macOS avoids indexing temporary agent workspaces.
- Releases preserve a candidate captured at kickoff so later development cannot silently change the version being validated.

## Fixed

- Runway image generation accepts the model inherited from Settings without requiring a per-image override.
- Editing an automation rule waits for its provider choices before saving, preserving the selected model and effort.
- Canceling one settings read no longer cancels other pages' shared startup reads.
- GitHub inbox agents use the notification account's verified login instead of inheriting the PortOS repository's account.
- Storyboard fitting keeps every panel inside a short song and reports short shots without producing backward timing.
- GitHub notification updates no longer mistake a partial response for the full inbox or hide unread threads beyond the first pages.
- GitHub handoffs re-evaluate refused threads, recognize GitHub-owned bots consistently, and keep pinned accounts bound to the correct forge host.
- FableLoom shot planning checkpoints individual scenes, reports terminal outcomes once, and keeps durable work running when an older synchronous client disconnects.
- FableLoom outline contracts retain their intended fields and name mismatches, while episode connection depth counts dramatic scenes correctly.
- Health imports preserve existing records and concurrent edits, reject colliding blood-marker identities, and place daily records and profile fields where PortOS reads them.
- Overlapping practice results and agent activity writes no longer overwrite one another.
- Outlook calendar sync keeps history outside its fetch window; deleting an account or purging a chat also removes its derived Timeline and Tribe records.
- Conflict restoration retains storyboard plots, temporary tracks, beat pins, and card orientation.
- Brain and note editors preserve edits made during a save and keep the selected record and filters consistent.
- Older filter, range, or vault responses no longer replace newer selections across history, charts, feeds, savings, and Wiki views.
- Failed loads in social-agent tabs, goal link pickers, Writers Room, and Wiki reports show a retryable error instead of an endless spinner or misleading empty state.
- Failed stop, cancel, subscription, and background-save requests remain visible; refused video cancellation no longer reports success or detaches the active run.
- Video stitching refuses incomplete selections, clip coverage matches render timing, and saving an animatic outro frame waits for the capture to settle.
- Video history searches find older remix targets, and license attribution still includes the complete history.
- Stalled thumbnail, frame-extraction, and collage processes terminate cleanly, and sprite trim failures remove temporary frames.
- Interrupted model downloads settle correctly; stalled Ollama imports retain reusable weights until no process is reading them.
- Render cleanup preserves music-video finals referenced by FableLoom scenes, and invalid migration records cannot arm data purges.
- Ledger history reads remain consistent during rotation, shutdown drains scheduled work before closing the database, and late startup work respects shutdown.
- Paired peers can reciprocate their allowed sync, and local password-free operators can manage peers without granting remote callers that authority.
- Host-process routes, browser automation, account writes, and deferred media work enforce operator authority while preserving authorized local and agent workflows.
- Calendar names reach sync agents as untrusted data, scheduled Brain summaries run without host tools, and browser destinations and media prompts stay out of operational logs.
- Review Hub distinguishes stored pending work from an all-clear queue, commission cards show current render outcomes, and Wiki health reports display their complete formatted content.
- Managed merges validate structural compatibility with their actual target, preserve ownership holds, and recover deferred validation checkouts without discarding work.
