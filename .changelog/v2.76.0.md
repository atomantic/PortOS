# Release v2.76.0 - Benchmark Badger

Released: 2026-09-24

## Highlights

- **Model insights:** Models → Comparison now starts with sourced public benchmark and pricing observations, while Models → Performance is where you discover providers and run or review your own benchmarks.
- **Broader app quality checks:** App Quality now covers service, data-platform, API, privacy, reliability, cost, and infrastructure concerns, and skips checks that do not apply to an app.
- **More predictable agent runs:** Tasks honor the model or tier you selected and the provider's configured default; run cards explain when a learning suggestion uses a weaker tier.
- **Safer cross-machine logs:** Repeated drink and nicotine entries stay distinct across peers, and edits, date changes, and deletions converge without resurrecting removed entries.
- **Clearer service health:** PortOS now distinguishes an unavailable process manager from a healthy empty process list, avoiding false status reports and restarts.
- **More reliable navigation:** When a page has a stale cached asset, PortOS can recover and retry without undoing a newer navigation.
- **More focused 3D downloads:** Procedural graph views no longer download the asset-import support used by 3D model and avatar views.

## Added

- Models → Performance adds a five-task benchmark for enabled free, subscription, and local providers. Results retain scores, token counts, timing, and token basis without saving prompts or responses. Cost comparisons are labeled as API-equivalent estimates; subscription and local inference costs remain unknown.
- App Quality adds scheduled audits for service reliability, data integrity, privacy, cost efficiency, and infrastructure, alongside broader API and service guidance.
- User task forms can scope a task to an app, and goal-fidelity tasks can include attached screenshots.

## Changed

- Models → Comparison reads a release-shipped catalog of dated, sourced public performance and pricing observations. Provider discovery, explicit task benchmarks, and their history live in Models → Performance.
- The App Quality page brings its score, history, and category breakdown together, and the score counts only applicable categories. Scheduled checks can still honor a check the user selected explicitly.
- Task model and tier choices resolve on the provider that runs the task. The Claude Code CLI and TUI defaults move to Claude Opus 5.5, while existing model pins stay in place.
- Quality scheduling spreads checks across all seven days and explains when an audit batch skips checks that do not apply.

## Fixed

- Peer-synced drink and nicotine logs now preserve separate repeated events and converge on edits, date moves, and deletions.
- Failed page assets recover with a clean cache while preserving lazy module order and the destination route.
- Process and app status report PM2 read failures as unavailable rather than as an empty or healthy process list.
- The agent prompt now includes the configured Digital Twin context, and provider model-list edits survive saves.
- The iTerm2 terminal view restores scrollback. Agent task creation, issue preloads, and review recovery also report or retain their work when a tool, provider, or worktree is unavailable.
