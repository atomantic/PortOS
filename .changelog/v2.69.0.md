# Release v2.69.0

Released: 2026-09-17

## Highlights

- **Every AI backend PortOS can reach now lives in one table, and a connection is one instance of it.** A connection carries its own name, plan, and enabled flag, so two accounts on the same vendor — a free tier and a paid one — are separate rows with separate model catalogs, and the usage report can finally tell them apart.
- **A harness gets its backends by capability, not by hand-wiring.** Adding a CLI or TUI agent now describes which services it can reach; PortOS composes the executable route (keys, endpoint, config) itself, including its own direct HTTP client as a first-class harness alongside the CLIs.
- **Adding an agent harness creates its CLI and TUI cards together,** keys fan out to the mode sibling automatically, and Kilo Code, OpenChamber, and generic credential-bootstrap harnesses join the list. Deleting a provider or a backend connection now asks first.
- **Streaming API agent runs stopped dying for the wrong reasons:** responses split across network reads are reassembled instead of failing the run, an empty keep-alive frame is read as a heartbeat, a healthy long stream is no longer killed at the hung-provider ceiling, and a run you stopped is recorded as canceled rather than an unknown provider failure.
- **The private Eidoverse world keeps running between mind wakes.** Supervised controllers — a resource tick, an ambient verb, a gentle NPC — keep ticking while the mind is away, with behavior PortOS ships and only the controller's id authored by the install.
- **Eidoverse foundations can be promoted into the shared baseline and inherited across peers.** Promotion re-runs ownership, resilience, privacy, and federation checks against the body as it stands; a full-sync peer pulls the promote envelope alone, never a ledger record.
- **Turning on an app's quality audits is now one form instead of twenty-five cron expressions.** PortOS spreads the applicable audits across the week, orders them by the catalog's suggested chain, avoids hours the app already uses, and schedules a claim drain after the checks that file issues.
- **A custom scheduled task can be run ad hoc from its card with its own configuration** — fill in the fields, press Run now, and that one run is re-aimed without touching the saved task.
- **Voice model provisioning is provider-agnostic and defaults to Ollama,** reporting real per-model tool capability instead of guessing from the name; existing LM Studio installs are pinned to LM Studio and keep working. Voice never probes or downloads a model while it is disabled.
- **The unattended updater got more careful:** it refuses while an LLM run or a backup is in flight, stops re-queuing its repair agent every tick forever, checks for an in-progress update before writing, and surfaces a failed write instead of looking like a normal cooldown.
- **Accessibility fixes across forms and widgets** — a visible keyboard focus ring is back on form fields, field hints are announced with their control, the upcoming-tasks widget announces its unavailable and stale states, and job-form buttons meet the 44px touch-target minimum.

## Added

- Service definitions: one catalog of every backend a harness can be pointed at — subscription services, API-key vendors, hosted gateways, local runtimes, and fleet hosts — with per-harness capability bindings and a `direct` harness for PortOS's own HTTP client.
- Service instances: a connection carries a unique name, a plan, an enabled flag, and its own model catalog, refreshed through the definition's own strategy (probe the endpoint, ask the local daemon, ask the signing-in harness, or use the declared list).
- Kilo Code and OpenChamber as first-class agent harnesses, plus a generic credential-bootstrap provider configuration for CLI/TUI harnesses that sign in through a wrapper.
- A TUI sibling can be added to an existing CLI provider straight from its card, and a harness's CLI and TUI records are created together from one add.
- Eidoverse supervised controllers, with two shipped behaviors: an ambient beacon that marks a pulse every Nth tick, and a lantern keeper that keeps an author's lamps lit across host restarts.
- An Eidoverse Controllers panel beside Foundations under World controls.
- Promotion of an Eidoverse foundation into the shared baseline, from the UI or from a granted mind, behind a default-off grant that sits on top of world-management permission.
- Cross-instance foundation provenance and inheritance, with peers pulling promoted foundations on the regular sync sweep.
- A quality-audit scheduling form on an app's Quality tab that places the whole week's audits in one pass.
- A configuration form for scheduled agent jobs, and configuration fields rendered on a custom task's card for ad-hoc runs.
- A Do:Review action on the app PRs tab for any open GitHub pull request.
- Refresh Models on the Kilo and Grok provider cards.
- App-scheduled tasks now appear on the Schedule Timeline instead of being dropped.

## Changed

- A provider's model list is scoped to the plan you actually pay for, so a catalog no longer advertises models your subscription cannot call.
- The reasoning channel is recognized under every name providers give it and salvaged when a run times out, so a long think is not lost with the run.
- Voice provisioning moved to a backend registry: Ollama and LM Studio are implemented, and a remote OpenAI-compatible provider correctly reports that it has nothing to provision.
- Machine-identity and PII redaction converged onto one shared pattern list while each consumer keeps its own output vocabulary.
- Ollama prompt budgeting accounts for the context length the daemon was actually launched with, not just the provider's configured window, including the untrusted-content floor.
- CoS claim worktree directories are namespaced per managed app.
- The app Automation tab uses the full desktop width, with labeled Run now / Edit / Details actions in place of unlabeled glyphs.
- Task descriptions are bounded in CoS agent listings, so the Agents page loads on a slow link.

## Fixed

### Agent runs and providers

- A response split across network reads is reassembled instead of failing the run, and an empty data payload is treated as a keep-alive heartbeat rather than a bad frame.
- A healthy streaming API run is no longer killed at the hung-provider ceiling.
- A run stopped by hand is classified as canceled instead of an unknown provider failure.
- Stop, timeout, and cancel reach the harness behind a credential-bootstrap wrapper.
- A keyed non-gateway service keeps its key on an OpenCode route, and only OpenAI URLs are recorded as an endpoint.
- A mode-sibling key fill is refused when the two modes name disjoint halves of a connection, and a TUI mode is refused for a harness already paired under a CLI id.
- Voice bootstrap no longer chases a dead LM Studio API server; an unreachable backend reports once instead of retrying the whole install chain.
- A mind surfaces an actionable pause when the local context budget is too small, instead of failing opaquely.

### Scheduling, CoS, and self-update

- The unattended updater is blocked while an LLM run or a backup is in flight.
- The auto-update repair agent no longer re-queues itself every tick forever, and repair dispatch is separated from the update cooldown.
- An in-progress update is checked before the arming write, and a runtime write failure is surfaced rather than reported as a normal cooldown.
- Armed creative-commission crons are preserved when the inventory read fails.
- A commission run whose history write was lost is surfaced instead of reported as plain success.
- Commission pre-fire read failures are recorded and propagated instead of silently doing nothing.
- Scheduled job failures and CoS maintenance timer failures are logged with a stack instead of being swallowed.
- The improvement-check wake-up calculation retries instead of sleeping through a cron minute.
- A stalled perpetual-drain forge probe is surfaced and escalated.
- Branch reconcile and the PR watcher poll each repository with its own credential.
- A re-aimed ad-hoc run is no longer dropped as a duplicate of the saved task.

### Git and terminals

- An abandoned git lock is cleared in the pull, fetch, and rebase paths, and submodule checkout recovers from one instead of wedging forever; a `.git` file that names no gitdir is refused rather than swept.
- A TUI's terminal modes are restored when the replay buffer has dropped them.

### Eidoverse

- A failed collection no longer flaps the visit marker.
- A mind can see its own Eidoverse before it talks about it.
- The controller store lock is released before a tick reaches the world.
- A promote candidate that leaks through a key name is refused, and the promote gate confirms on screen rather than only in the row's state.

### Interface

- A visible keyboard focus ring is restored on form fields, and field hints are associated with their controls for screen readers.
- The upcoming-tasks widget announces its unavailable and stale states.
- Job form field buttons meet the 44px touch-target minimum, and the nav footer no longer overflows.
- The controllers panel's initial load is gated on the component still being mounted.
- The n-back demo starts paused when its card mounts into a hidden tab, shows a repeated letter as a new stimulus, and presents the rule as a running stream instead of describing it.
- The creative tool suite no longer reads the developer's own install settings.
- Scraped plan names keep their 60-character cap when interior spaces are allowed.
