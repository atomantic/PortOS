# Client conventions (`client/src/`)

These apply to React/Vite client code. The root `AGENTS.md` rules (functional programming, error handling, single-line logging, Zod validation, Security Model, Sensitive Data & Privacy) always apply. Rules marked *enforced* have a tree-wide test under `client/src/` that names the offender; the test file carries any allowlist.

## UI conventions

- **Actions look like buttons**: a border, padding and hover/focus treatment; plain text links are for navigation and references. Keep controls usable on touch.
- **Fix missing prerequisites in place.** Show the missing tool or setting beside the blocked action, offer the existing setup/check controls there, and preserve the user's work. If setup happens outside the app, give concrete steps and a retry. For linked records, locks or approvals, link or button to the exact place it's resolved, not just a disabled control, and keep that destination reachable for stale and already-approved records. Keep existing authority checks.
- **Timestamps display in browser-local time** via the shared formatters in `utils/formatters.js`; never render an ISO/UTC string. ISO stays for transport and persistence; explicit schedule timezones and date-keyed reporting keep their semantics.
- **Admin workspace design**: new or redesigned admin pages follow [the workspace design guide](../../docs/UX_DESIGN_GUIDE.md) (page family, useful work first, desktop width for related work/evidence, icon-prefixed desktop nav, CoS-style compact mobile icon rows). Apply incrementally; it does not authorize unrelated behavior changes or a global CSS rewrite.
- **No `window.alert`/`confirm`**: use inline confirmations or toasts.
- **Form labels pair `htmlFor` with the input's `id`**; visual styling doesn't create the association.
- **Narrow containers on desktop** follow the [narrow-container contract](../../docs/UX_DESIGN_GUIDE.md#narrow-monitors-and-embedded-containers): container queries, shrinkable grid/flex children, wrapping actions, long-string handling. Verify child rectangles as well as scroll dimensions; hiding overflow is not a fix.
- **Mobile responsive, always.** A `grid-cols-N` with N > 3 and no `…:grid-cols-*` in the same class string is a bug: give text-bearing cards a phone default and widen by breakpoint (`grid-cols-2 gap-3 sm:gap-4 lg:grid-cols-4`); a wider gap is not a column breakpoint. Square thumbnail/heatmap grids may stay 4+ on a phone but still need a breakpoint. *Enforced:* `responsiveGridConventions.test.js`.
- **A shared primitive baking in `inline-flex` must yield to the caller's display utility**, because Tailwind v4 sorts `.inline-flex` after `.hidden` and it wins (`hidden sm:inline-flex` stays visible). `Pill` handles this (`OWN_DISPLAY` in `components/ui/Pill.jsx`); `InfoTooltip`, `CopyableId` and `ProvenanceChip` need the same fix the first time one gets a `hidden md:` call site. `flex`/`grid` primitives are unaffected.
- **A fixed-width popover of 256px or more (`w-64`+ or an equivalent `w-[…]`) also carries `max-w-[calc(100vw-1rem)]`**: `Layout`'s shell is `overflow-x-hidden`, so a too-wide panel is clipped, not scrollable. *Enforced:* `popoverClampConventions.test.js`.
- **A hover-revealed control stays visible on touch**: Tailwind v4 wraps `hover:` in `@media (hover: hover)`, so scope the hide to hover devices (`[@media(hover:hover)]:sm:opacity-0`, see `components/Layout.jsx`) or restore it with `pointer-coarse:opacity-100`. *Enforced:* `hoverRevealConventions.test.js`.
- **An icon-only button gets a 44px hit area in both dimensions** (`min-h-[44px] min-w-[44px]`, or `pointer-coarse:min-h-11 pointer-coarse:min-w-11` for a dense desktop row). Bare `<summary>` rows get it from `src/index.css`. *Enforced:* `a11yConventions.test.js`.
- **A dnd-kit drag handle carries `touch-none`** on the element spreading `listeners`, or touch drags cancel as pans. A source that must keep native panning (the Video Timeline segment block) uses a long-press `TouchSensor`. *Enforced:* `dragHandleTouchConventions.test.js`.
- **Size form fields for their content.** Short selects and numeric inputs share rows when there is room and stack on narrow screens or drawers; prefer bounded wrapping grids (`grid-cols-[repeat(auto-fit,minmax(min(100%,18rem),24rem))]`) over full-width controls. Keep labels and help with their fields, preserve tab order, give prose editors and long paths room, and avoid global input width limits.
- **A sub-nav that doesn't fit a phone collapses to icon links, never a `<select>`** (product preference; #7283 made it a select and was reverted). Pass `mobileCompact` to `TabPills`, which renders icon-only tabs below `sm` with `max-sm:sr-only` labels; `RouteTabsHeader` decides whether to collapse (`MOBILE_COMPACT_THRESHOLD`). **Reuse `TabPills`; never roll a new tab bar.**
  - Every tab in a fixed set of sections needs a unique icon. Section tabs get theirs through `buildSectionNavTabs(getSectionNavTabs(s), NAV_PRESENTATION, s)`, which throws on a missing one (`lib/navPresentation.test.js` pins coverage and uniqueness).
  - The `<select>` fallback is only for unbounded, data-driven lists where every entry would share a glyph (FableLoomStory's episode list). Record pickers that happen to be selects (account switchers in `pages/X.jsx`, `pages/StackerNews.jsx`) are not sub-navs.
  - *Enforced:* `subNavConventions.test.js` (flags `border-b-2` tab strips outside `TabPills`).
- **Above the fold**: keep actionable content and information visible without scrolling.
- **No hardcoded localhost**: build URLs from `window.location.hostname` (the app is used over Tailscale).
- **Chrome floating over media uses `.port-media-overlay`** (`-strong` for small labels on photos, `-item` for its buttons, `-divider` for separators; all in `index.css`, which also says when to use `.always-dark` instead). Never `bg-black/NN` + `text-white`/`text-gray-N00`: day mode turns the text dark on the black scrim. Older overlays still use that idiom (#3796); follow the new convention, not the neighbor.
- **Alphabetical navigation**: sidebar items in `Layout.jsx` are alphabetical after the top single-row section (Dashboard, Review Hub, Eidoverse, Goals) and its separator; children in collapsible sections are alphabetical too.
- **Space is a global push-to-talk hotkey.** A surface that owns Space (a timed drill, keyer, transport) claims it with `useKeyCapture`. Global key handlers (`useKeyCapture`, `useKeyboardShortcuts`, the voice widget) stand down for native button activation through one predicate, `shouldIgnoreGlobalKey(event, opts)` in `lib/a11yKeyboard.js`; add new guards there, never at one caller (#4748). A surface that owns a key spreads `noPointerFocusSurfaceProps` on its root so a click that parks focus on an inner button doesn't take the key over.
- **Never `autoFocus` a control that appears in response to a key-submit**: the still-down Enter activates it the moment it mounts. Keep the submitting element focused (`readOnly`, not `disabled`) and filter `e.repeat` (`MorseTrainer.jsx`), or handle Enter-to-advance in a window handler gated on `shouldIgnoreGlobalKey` with the button unfocused (`PostDrillRunner.jsx`).
- **Web Storage goes through `lib/safeStorage.js`** (`safeReadStorage` / `safeWriteStorage` / `safeRemoveStorage` and their `Json`/`*Session` variants). `localStorage`/`sessionStorage` throw in Safari private mode, sandboxed iframes, disabled cookies and at quota, and neither `typeof` nor `?.` guards that; a raw read in render unmounts the route (#5689). *Enforced:* `storageConventions.test.js`.
- **Push, don't poll.** Fetch once, then update from Socket.IO events (`useSocketSubscription`, the media-job hooks) and apply your own mutation's response immediately. A change with no event gets a server emit (declared in `server/lib/socketEventContracts.js`), not a client poll. Exceptions (hardware telemetry, external systems with no callback, PortOS self-restart): [Realtime updates, not polling](../../docs/UX_DESIGN_GUIDE.md#realtime-updates-not-polling).
- **A sanctioned poll uses `useAutoRefetch(fetchFn, intervalMs, { enabled, pollOnly: true })`** (`hooks/useAutoRefetch.js`), never a hand-rolled `setInterval`: it pauses in hidden tabs and refires on return (#5697). Pass the existing gate as `enabled` rather than an early `return`, and `immediate: false` when another effect owns the first fetch. *Enforced:* `pollingConventions.test.js`.
- **No local binding shadows a timer or `fetch`** (`setInterval`, `setTimeout`, `clearInterval`, `clearTimeout`, `requestAnimationFrame`, `cancelAnimationFrame`, `fetch`); a later call in that scope silently hits the local (#5728). Name the binding for what it holds. *Enforced:* `globalShadowConventions.test.js`.
- **An async effect keyed to a switchable identity drops superseded responses**: `let active = true;`, gate every `set*` on it, `return () => { active = false; };`. Otherwise switching records faster than the request renders the previous record's data under the current one, and controlled children never self-correct (#7242). `useMounted()` does not cover this. Where the response must match the newest request (e.g. the effect writes a value in its own dependency array), compare a generation ref instead (`IngredientPicker.jsx`). *Enforced:* `asyncEffectDisposalConventions.test.js`.
- **User-facing counts and amounts use `formatCount` / `formatUsd`** (`utils/formatters.js`): thousands-grouped, en-US pinned (`2,762`, `$4,610.09`). `formatCount` shows `—` only for missing/unparseable input; pass `{ fallback: '0' }` where an absent count should read zero. *Enforced:* `numberFormattingConventions.test.js` (no bare `.toLocaleString(`). Other formatters (`formatBytes`, `timeAgo`, …) live beside them.
- **List deletion preserves place**: after the server confirms, collapse the row and its spacing with `components/ui/CollapsibleListItem`, then remove it from local state. Keep the list and scroll container mounted, keep filters and pagination, refresh counts separately, and never swap content for a loading placeholder. Keep failures visible, guard duplicate requests, honor reduced motion, and move focus to a surviving row/container with `preventScroll`. Spacing goes inside the collapsing wrapper.
- **Reactive updates**: after a create/update/delete, update local state (`setState(prev => prev.filter(...))`) instead of refetching the list.

## API errors and save gating

- **Silent vs toasting requests.** `request()` in `client/src/services/apiCore.js` toasts errors by default. A caller that owns its error UI (`useAsyncAction`, or a `.catch` that swallows on purpose) passes `{ silent: true }` so only one layer toasts; give new API wrappers an `options` parameter.
- **"Run Now" gates on saved state, not the form.** A button that triggers server work reading server-side settings stays disabled while the form is dirty or saving: track a `saved*` value per dependent setting, updated on successful save. A tooltip warning is not enough.
- **In-flight saves gate dependent actions too.** While an async PATCH of a field is pending, disable buttons that read it: set a `<field>Saving` flag before the PATCH, clear it in `.finally()` (`lengthProfileSaving` in `client/src/pages/PipelineIssue.jsx`).

## Routing and deep linking

- **Tabbed pages use URL params**, not local state (`/devtools/history`, not `/devtools` plus tab state).
- **Every selectable record is deep-linkable.** A view that opens a specific project, item, scene, editor or master-detail selection encodes it as a route param (`/music-video/:projectId`, `/media/creative-director/:id/:tab`), never `useState`/`selectedId`. Selection `navigate()`s to the id route, delete/clear `navigate()`s back to the index, and stale ids render a not-found fallback. Register both the index and `:id` routes in `App.jsx`, and the base path in `NAV_COMMANDS`.
- **Pick the right Layout scroll mode for a new page.** The shell is declared by where the `<Route>` sits in `App.jsx`: under the pathless `<Route element={<FullWidthMain />}>` or `<Route element={<PaddedMain />}>` (`components/PageShell.jsx`, which renders `<main>`); never classify by pathname. Normal pages use `PageLayout` (a `PageHeader` as `header`, optional `TabPills`/`RouteTabsHeader` as `navigation`, content in the internally scrolling body) and go under `FullWidthMain` so there is no second gutter or scroller; keep bounded reading widths inside the body. Editors override `bodyClassName` only when their panes own scrolling (CoS). Document/form routes such as `/apps/create` go under `PaddedMain`. A param route that mounts the same page as its index shares the index's shell. Exceptions: `docs/PAGE_LAYOUT_AUDIT.md`.
- **Moving a page leaves no hand-written redirect.** List the old path in its `NAV_COMMANDS` entry's `previousPaths`; App.jsx generates the redirect (suffix, query and hash carried). Only redirects with real logic (canon, harness connections, `/video/:id`) stay hand-written.

For the full new-page checklist (nav entry shape, palette actions, voice aliases), invoke the `portos-add-page` skill.

## Config drawers

Settings-over-a-feature surfaces use the shared `client/src/components/Drawer.jsx`, never a hand-rolled `fixed inset-y-0 right-0` clone (design record: `docs/plans/2026-07-01-drawer-ux-redesign.md`).

- **Size**: `size` is `sm` 520px, `md` 640px, `lg` 720→880px, `xl` up to 1100px; widen large forms so they lay out in columns, keep small dialogs `sm`. Mobile is always full-width. `widthClass` is a back-compat override.
- **Tabs**: a large surface (many fields or groups, e.g. Edit App) uses `tabs={[{ id, label, icon?, count? }]}` + `activeTab`/`onTabChange` and renders only the active tab. A medium form that should stay fully visible uses labeled sections instead (`ImageGenSettingsForm`'s `grouped` prop).
- **Per-tab scroll** remounts the body on switch, so **all mutable form state lives in the parent**, never in uncontrolled inputs (see `EditAppDrawer.jsx`). Validate unmounted tabs at Save and `setActiveTab()` to the failing one.
- **Tab bar**: the built-in layout wires `TabPills` (`mobileCompact` under `sm`). A surface hosted in both a drawer and a page (like `ImageGenTab`) renders its own `<TabPills variant="pills" mobileCompact>`.
- **Deep-linkable tab**: drive `activeTab` from `useDrawerTab(paramName, defaultTab, tabIds)` (`client/src/hooks/useDrawerTab.js`); the caller names the param (`appTab`, `mediaTab`) and passes the id list so a stale link falls back to `defaultTab`.
- **Long-lived forms** set `closeOnEsc={false}` / `closeOnBackdrop={false}`.
- **The overlay is always portaled to `<body>`**; never re-nest it. A `filter`/`backdrop-filter`/`transform` ancestor (glass themes give `.bg-port-card` a `backdrop-filter`) becomes a fixed element's containing block (#4150). Any new hand-rolled `fixed inset-0` overlay is portaled too (`Modal`'s `usePortal`, `GalleryImagePicker.jsx`).
- **Examples**: `client/src/components/apps/EditAppDrawer.jsx` (built-in tabs, `size="lg"`, `useDrawerTab('appTab', …)`) and `client/src/components/settings/ImageGenTab.jsx` (internal pill sub-tabs, `useDrawerTab('mediaTab', …)`).

## Large collections and incremental loading

Every potentially growing list (Brain inbox/memory, agent history, image history, …) follows [the collection-loading contract](../../docs/UX_DESIGN_GUIDE.md#large-collections-and-incremental-loading): fetch only the active route's data, start with a bounded server page, and hydrate large details on demand. New infinite lists use `usePagedCollection` and `InfiniteScrollFooter`; don't copy observer/request/race logic. Client-side slicing of an unbounded response is not pagination. Stable collections (apps, providers, histories) refresh through targeted socket invalidations and reconnect recovery, not whole-list polls; any telemetry poll is justified, bounded, visibility-gated and limited to an open consumer. Query-wide search, counts and selection URLs stay correct; never search only loaded rows. Existing exceptions migrate incrementally with tracker coverage.
