# Splash: local Inkling 2 Mini (opt-in)

Splash is a separate Apple Silicon inference server, not an Ollama or MTPLX option. The supported pilot is [Splash 1.7.2](https://github.com/incoai/splash/releases/tag/1.7.2) on macOS 26.4+ and Apple M3 or later. PortOS does not install, download, launch, stop, or select it automatically.

1. Install the vendor CLI from the release. On the Mac running PortOS, open **Models → Runtimes → Splash → Configure** from the roster. Copy the launch command into a terminal on the Mac and leave it running. It binds only to loopback on port 8001 and announces the stable model ID `inkling2-mini`. The first start downloads the GGUF and paired speculative draft; ensure room for several tens of GB. Port 8000 remains available to your other local servers.
2. Use **Check Splash status** after the terminal reports ready. This checks the engine and advertised model without making a generation request. A different launch port is a manual provider edit; this card checks the shipped port only.
3. In **AI Providers**, enable and select **OpenCode · Splash (local)** or **Claude Code · Splash (local)**. Both reach the same server. OpenCode uses the OpenAI-compatible `/v1` root and declares a local auxiliary model; Claude Code uses the Anthropic-compatible server root. The optional **Splash (local)** provider is the direct OpenAI-compatible API route. All ship disabled. Nothing changes your active provider or defaults.
4. To free memory, stop the process in its terminal with Ctrl+C. PortOS won't restart it or offer automatic idle/startup management.

Splash uses `reasoning_content` for the OpenAI-compatible tool loop, not the Ollama-specific `reasoning` field. Claude Code uses its native structured thinking blocks. This pilot was tested with OpenCode 1.x. The vendor launcher uses standalone mode for OpenCode 2; the PortOS preset does not select that mode. Both presets use a 65,536-token context ceiling. OpenCode sets aside 8,192 tokens for output and uses the remaining context for prompts and compaction. Check `/v1/models` after launch; if available RAM results in a smaller served window, lower the preset's context to match (Claude Code's `CLAUDE_CODE_MAX_CONTEXT_TOKENS` or OpenCode's inline model `limit`). Actual speed, useful context and time to a passing patch depend on weights, memory, and the workload.
